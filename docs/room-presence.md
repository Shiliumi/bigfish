小屋环境接入与聊天拍照（1.16.2）

此前 `fish_room inspect` 只返回三件可移动物品和可放置表面。模型把操作范围误读成整个房间，因而否认了画面中已有的花盆、书架；拍照只接在界面按钮上，模型没有拍照工具，又把渲染照片误解为需要现实摄像头。

当前行为

- 场景与模型共用物品目录：床、鲸鱼玩偶、床头柜和台灯、电脑书桌、椅子、书架、绿植、装饰画、海景窗、地毯都有说明。场景创建物品组时校验目录，固定物品与三件可移动物品分别返回。
- 主聊天常驻简短房间身份与能力说明。房间、家具、窗边、自拍等相关提问才读取当前宿主状态，包含灯光、时段、雨雪、物品位置与锁定；普通闲聊不额外读取房间或加入整份目录。回忆上下文预算仍考虑新增信息。
- 当前状态优先于旧回答中“没有花盆、没有书架、需要摄像头”的错误推断。日常自然称作自己的房间，不必每次报坐标或解释底层实现，也不虚构未经执行的活动。
- 房间氛围迁移到本机服务保存，首次从原有设置接续，使用独立版本校验。布局草稿保持原样；模型和照片读取已保存布置，不自动保存或丢弃用户正在拖动的草稿。
- `fish_room photo` 支持全景或窗边。请求交给当前应用的独立渲染器，即使正在聊天、小屋页面已经卸载，也能按需生成新 PNG，返回照片回执和可直接展示的 Markdown。不调用现实摄像头或截取桌面。

拍照执行边界

应用只常驻轻量请求监听；收到任务时按需加载三维模块，使用指定布局与氛围渲染一张图，随即释放场景、纹理和图形上下文。没有新增定时模型任务或常驻隐藏的三维动画循环。

请求继承桌面鉴权、客户端标识、同源和项目绑定。任务使用唯一 ID、一次性渲染租约与 25 秒时限，重复请求复用该任务回执；旧版本、错误租约、无效图片或超时均明确失败，不拿图库旧图冒充刚拍的照片。应用退出、旧版界面未加载渲染监听或图形不可用时，会说明没有拍成。

照片是三维房间的渲染画面，角色采用现有高清待机素材；不代表现实摄影或模型已拥有视觉能力。花盆、书架等固定物品现已正确提供给她，但暂未开放移动，这时应说明“有，只是当前不能挪”，不能说不存在。主动自拍与后台自主布置仍未启用。

实际验证

- 456 项 Python、91 项 Node 测试通过，TypeScript 与生产构建通过。新增验证包括完整家具目录、氛围持久化/冲突、房间上下文主题限制、当前原话约束、渲染租约、重复请求、布局变化、图片损坏、超时和服务关闭。
- 已安装适配器通过当前固定版 Hermes MemoryManager 路由接到实际应用渲染器；隔离页面卸载小屋组件后仍生成新照片，夜晚雪景与回执一致。
- 使用用户当前配置的 DeepSeek 模型，配合已安装的系统说明、宿主状态、真实工具路由和隔离房间做自然语言回归，未强制选择工具。给出旧的“没有花盆和书架”回答后，模型明确纠正为有绿植、花盆及书架；随后选择 `photo` 工具，在回复中附上新生成的图片链接。
- 模型验证只使用隔离测试对话与房间，没有发送用户真实聊天历史或调用长期记忆采集。生产应用另做了聊天页面中的实际渲染检查，保留既有草稿和聊天。
- 连续 1 小时后台、真实系统休眠与完整输入法验收仍未完成；短时按需拍照检查不能替代这些测试。

更新沿用 `python3 scripts/install_memory.py`（适配器 1.6.16）和现有构建步骤，不运行个人资料初始化、不改核心人设、不重建 cron，也不需要重启后台 gateway。空闲时重载项目 UI 服务和内部 Hermes API，再重载应用页面，已有对话的后续回合即可加载新版；历史消息保持原样。
