# 接错话后的修复与短答取舍

后续 1.6.5 补充了 [近期反馈延续与停止展开判断](conversation-feedback.md)，以下保留 1.6.1 的历史验证条件。

2026-10-29，记忆适配器 1.6.1 更新现有本地接话提示，不增加界面、工具、持久情绪状态或日常模型调用。应用仍为 1.14.2，静态 SOUL 和私人设定不变。目标是收到明确反馈后及时调整，不把关键词识别当作通用接梗能力。

## 参考与取舍

[近期社区讨论](https://www.reddit.com/r/AItexting/comments/1xg3ctz/what_ai_chat_apps_are_you_guys_using_lately/) 反复提到长聊中的一致性、记忆和重复问题；这些是个人经验，不作为效果证明。[Persisto Mate 的公开实现](https://github.com/m-rui001/mate-sillytavern/blob/main/index.js) 有运行时状态提示，并通过额外的模型请求评估最近对话的情绪变化。本轮只借鉴“当下材料影响取舍”的思路，不引入情绪数值或额外评估调用。

另外查看了 [HerAndHim 的持久会话实现](https://github.com/ericwang915/HerAndHim/blob/main/herandhim/core/persistent_agent.py)：它区分恢复的聊天历史与重新建立的系统消息，并在后续注入当前记忆。本项目不复制它的代码，也不把模拟日常生活或亲密度搬进来；先改善现有提示在明确反馈下的使用方式。两个所读源码文件 blob 分别为 `b02244c8f910cf4c16b8bd62e508ec97265acf03`、`b023a3b52c1bd56f022d0ba5b8dab64c264011d2`。

## 具体变化

- “你没听懂”“不是这个意思”“别猜了”“先不聊这个”等明确反馈进入已有 feedback 分支。提示先联系原话与上文改口，不重复解释，不说自己早就明白；停止展开的要求优先。该分支沿用既有的兴趣推送和表达试行抑制，不建立新的长期用户事实。
- 技术任务和明确难受仍按原优先级处理，不因出现“你没懂”就耽误排障或继续玩笑。引号、代码和引用块中的文字先排除，补上中文单引号 `‘’` 的引用识别；这是有限的文本规则，不是完整的引用或意图解析。
- focused 提示明确尊重“一行”“只给代码”等篇幅要求。它影响模型取舍，不截断或重写模型输出，也不保证模型一定遵守。
- 普通闲聊仍不增加空提示包。新增反馈分支的示例提示包约 147 字符；focused 包从 114 到 129 字符。这里是字符数，不是 token 或账单节省率；有反馈时会多占少量输入。

## 对比工具修正

此前付费回放的两版 SOUL 和适配器说明虽各取对应版本，本地提示却都由当前 `fish_conversation.py` 生成。这些旧报告只能按当时共同使用的动态提示条件理解，不能当作两套完整历史实现的端到端对比。

新 `conversation_probe_context.py` 分别加载显式选择的本地 Git 源码和工作区源码，对同样的虚构记录生成各自提示，并保存源文件哈希。逐轮对话仍使用各版自己本次实际生成的助手历史，没有把期望回复灌进历史。新测试用两个不同实现验证不会再次串用提示；另检查场景隔离、真实生成历史的完整交替形式。运行时 Journal 与 tokenizer 使用当前版本，报告不是整个历史软件栈的重建。

## 本轮验证及未解决问题

新增四组三轮虚构材料 `conversation_repair.json`，包含误解调侃、把猫踩键盘误判为驱动问题、只要一行代码、夸奖后切回正事。用户消息与评阅要点在首次推理前固定，评阅要点不传模型。后续新增的停止展开措辞及单引号处理由程序测试验证，未另做付费生成验证。

```bash
python3 -m unittest discover -s scripts -p 'test_*.py'
node scripts/probe_conversation_play.mjs --live a28261b --interactive --fixture=conversation_repair.json
```

第二条是显式付费开发命令，读取当前模型连接，计入既有后台额度；只有公共提示和虚构文本发送出去，输出不执行、结果私下保存在 `.setup/`。本轮 `deepseek-flash`、temperature 0.7、输出上限 640，完成 7 条后下一条被额度拒绝，没有提高额度、绕过记账或重试补齐。已完成回复均正常结束，无工具标记或截断；用量合计 24,070 tokens，含缓存输入和输出。

已完整比较的只有第一组三轮。两版都能接受调侃并收住，新版首轮仍把“能吃”解读成“嫌嘴大”；不能据此判为明显优于原版。第二组只得到新版首轮，出现“我刚才查驱动去了”的无执行依据说法，保留为失败记录；其余组没有生成结果，不能声称短答遵守率提高或所有场景通过。没有自动评审模型或通用自然度分数。

全部 Python 238 项通过。实际安装适配器与固定 Hermes 的 `MemoryManager` 还在临时虚构目录中验证：反馈与停止展开选择正确，技术任务优先，引用不触发反馈，普通闲聊没有新提示；不生成模型回复、不写入真实会话。上述程序检查证明提示选择，不证明幽默或人格质量。仍须通过后续真实体验发现生硬之处，避免不断叠加提示词。

## 更新现有安装

```bash
python3 scripts/install_memory.py
```

先在线备份记忆，安装器另存适配器代码备份；聊天空闲时重载 gateway 插件、重启内部接口。无需重新构建应用或运行 `setup_profile.py`。本轮没有修改 SOUL，动态提示在已加载新版适配器的后续请求中使用；已有会话缓存的静态人设仍按原规则保留，不改写聊天历史。
