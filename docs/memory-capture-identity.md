记忆采集身份修复 · 适配器 1.6.14

同一会话隔天再次出现完全相同的一问一答，旧采集方式可能把它当作上一次回调重试，丢掉第二次发生的时间。本版优先使用 Hermes 为用户消息和最终回复提供的稳定 message_uid，区分真实重复发生与同一事件的重复同步。

采集回执只保存消息身份组合的哈希与记忆 ID。只有最终回复、最近用户消息、内容及原生时间都匹配时，才使用该身份；缺少可靠元数据时保留原有采集行为，不猜测新身份。

数据库扩展为附加回执表和版本标记，不重写原有记录、修订、索引或语义向量。旧记录的回放可绑定原 ID，之后确实再次发生的原生事件另记一条。已更正、遗忘的事件不会因回调重试重新写回；过去已经合并的事件不做历史反推。

同文重复事件仍按既有召回与人格证据规则分组，不会仅因多记一次就变成两票独立人格证据。

验证：447 项 Python 检查通过；在临时档案中使用固定 Hermes 的 SessionDB、AIAgent 完成入口和 MemoryManager 验证延迟同步、重复回调、多模态文字、更正与遗忘。当前私人数据库副本的附加迁移检查通过，旧版读取器仍能读取。实际安装后确认适配器版本为 1.6.14，重载保留 gateway 进程；既有人设、配置、任务、来信、兴趣与原有记忆表的保全检查通过。

此修复不新增模型调用，不声称已经验证聊天自然度或 token 降幅。
