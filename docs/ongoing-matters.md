# 持续事项与上下文验证（1.13）

持续事项保存用户明确正在推进的目标、待解决问题和约定，区别于一般聊天片段和鱼的兴趣。它是本地状态记录，没有新增独立的提炼或情绪评审模型。

## 来源与状态

`fish_matters` 在主聊天中提供 list / remember / update。写入必须绑定当前真人消息中的原文片段，标题必须出自该片段；创建要求直接表达目标、问题或约定的线索，代码块、引号和 Markdown 引用中的线索不独立触发创建。更新核对事项主题、版本与当前原话；否定“完成”不作完成处理，模糊的“那件事”可能需要补充具体话题。这些是保守的文字规则，不是完整语义理解，实际调用取决于模型。

事项默认保留 90 天，进行中与暂停合计最多二十项。相关聊天最多注入两条；泛泛问“最近在忙什么”只取有效进行中事项。具体问已完成或暂停的事情，可以返回其当前状态。到期或来源待核实的内容不进入自动上下文。没有自动日程、截止日期推断、后台催办、旧聊天回填或人格成长加分。

`ongoing_matters` 和 `matter_events` 位于原有私有 `data/memory/episodes.sqlite3`。事件记录原话、来源会话、版本、时间，以及可用时的来源经历。真人消息哈希仅用于把异步保存的对应经历关联到正确事件，不参与性格评分，也不作为公开日志。面板的直接操作标为本地编辑，不伪造聊天引语。

关联经历的摘要意义被更正、有效期结束或失效后，事项先待核实；单纯固定或编辑别名不改变来源意义。面板保存表示用户重新核实当前状态，到期后需要明确续留。遗忘一条来源经历会在同一事务内擦除关联事项标题与全部进展文本，留下删除标记；晚到的绑定不会恢复已删除的来源。用户可在面板明确创建一条新的同名事项。原始 Hermes 聊天、已有私有备份和已发送给模型的上下文另行保留。

## 上下文与成本

回忆片段只在摘要完整重复于原话、且说话人对应时去重；更正后的原话本来就是当前摘要时仅保留一份。仍保留来源、版本、时间、说话人及所有非空元数据。没有新增内容的 null 字段省略，JSON 使用紧凑格式。摘要含有节选中没有的信息时继续保留。

普通 casual / neutral 回合在没有重复节奏和真实兴趣材料时，不再加一份与静态指南重复的动态提示；认真求助、低落和语气反馈仍提供对应提示。事项、回忆、接话提示与偏好的合并上限仍为 6,800 字符，优先去掉可选兴趣和低排名回忆。

运行 `python3 scripts/eval_context.py`，以提交 `f86119b` 为基线，比较同一 91 个手写虚构查询。脚本需要本地 Git 历史包含该提交，在临时目录运行，不访问实际聊天或模型。结果如下：

| 回忆片段总字符 | 40,851 | 27,653 |
| 原有来源与原话保留 | — | 是 |

回忆片段减少 13,198 字符，约 32.3%；这是检索材料的字符量，不是 tokenizer 测量、总提示长度、日常流量或费用下降。新的工具定义、事项材料及正常工具往返都有成本，实际开销可能增加。没有修改 Hermes 的消息位置或压缩引擎，未宣称缓存命中提高。

原有记忆回放的首条目标命中仍为 78/79，应留空仍为 12/12；深层转述缺口仍在，不因去重而声称解决。已有开发用例被反复检查过，不能当作独立盲测。

Node 的完整集成测试需要已经初始化并运行的内部服务。单独的 `ui/tests/matters.test.mjs` 在临时鱼塘中检查真实 Python 桥接，不接触实际数据。回归包含幂等保存、状态与版本、过期续留、凭据拒绝、来源更正、来源遗忘、晚到绑定、主题不明时拒绝修改，以及 cron / bot / 已结束回合不可写。
