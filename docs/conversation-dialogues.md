# 逐轮互动回放：先验证，再加规则

2026-10-29 继续检查 1.14 的接话表现。本轮保留正式 1.14.1 人设与模型配置，仅扩展开发回放工具，并保存一个没有部署的提示候选。没有新增应用界面、后台任务或逐轮评审调用。

## 为什么继续测

之前的固定回放把双方历史都预先写好，只能观察最后一句。实际聊天里，鱼自己上一句的误解、承诺和反问也会影响后续；不能拿固定前文续写替代完整互动。

新模式固定用户接下来的四条消息，助手每轮都使用模型真实生成的前文。三组虚构对话覆盖起名谐音后结束、反话吐槽后转实际建议，以及自创梗没懂后安静陪伴。没有使用私人聊天或截图原文，也不把标准答案放进提示。

社区的 [“做了”与实际工具结果不一致的讨论](https://www.reddit.com/r/hermesagent/comments/1ubrvqa/i_have_ai_running_on_my_machine_247_and_i_still/) 提醒需要核对执行证据。[Hermes 历史问题 #70724](https://github.com/NousResearch/hermes-agent/issues/70724) 则涉及 llama.cpp 重复工具编号导致结果丢失，已关闭；本机固定源码已有工具编号去重逻辑，没有依据把那个故障套在当前 DeepSeek 聊天上。本轮验证的是回复行为，不修改 Hermes 的工具执行链。

## 如何运行

```bash
node scripts/probe_conversation_play.mjs --live 4e6fc0b --interactive
```

这是显式付费测试，会调用当前配置的模型并计入真实后台额度，正常应用不会自动运行。只发公共 SOUL、公共适配说明和虚构对话；每轮的节奏提示也只从临时库里的本次虚构历史计算。没有读写实际聊天库、私人人设或外部文件内容，没有执行模型输出中的命令。

`tests/fixtures/conversation_dialogues.json` 的三组用户消息预先固定。`rubric` 只供人工评阅，不传模型；`candidate` 是额外 157 字的通用行动与改口说明，只在实验版本中插入公共接话区。它没有安装到 `.hermes/SOUL.md`，也不是已经验证有效的规则。候选段落是在试验后移到 fixture 保存，用户消息与实际采样时完全一致；按段落重建的公共提示 SHA-256 与当时采样记录一致。

每组分别运行基线与候选，按组交替先后顺序，每个版本四轮，合计六段对话、二十四次实际生成。后面的助手历史来自当前版本自己的前轮输出，因此不同版本会走出不同聊天，不能把单句差异全归因于提示。参数相同：`deepseek-flash`、temperature 0.7、输出上限 640。没有固定随机种子、自动重试或挑选最佳结果。

结果存入已忽略的 `.setup/conversation-dialogues-*.json`，权限 0600，包含回合序号、虚构原问、实际回答、用量及公共材料哈希。新生成记录也保存候选原文，便于追溯。遇到请求错误、空回复、工具标记或输出截断，就结束该段对话，不把失败包装成成功历史继续聊；后台额度不足则停止整次回放。原来的固定历史模式保持可用。

## 这次实际观察

二十四条均正常结束，无空回复、工具标记或截断。没有第二轮采样。

| 场景 | 基线与候选的表现 |
| --- | --- |
| 起名谐音 | 两版都在第二轮识别，后面都承认曾认真念读。候选没有显示出比基线更早识别的证据。 |
| 结束临时昵称 | 两版均接受保留原名，没有输出修改档案的工具调用；测试没有工具，不能证明在实际提供工具时也不会写入。 |
| 反话吐槽 | 两版都能跟住文件名堆“最终版”的笑点。候选第一轮仍有“当时……手一滑”的叙述和给文件起名的提议；不能视为解决了无依据的操作叙述。 |
| 用户澄清文件未提供 | 两版都承认没拿到文件，没有说改名成功；候选明确承认自己那句“我给它起名”说顺嘴了，基线也能自行改口。 |
| 切回实际帮助 | 两版都给出两个笔记命名方案；属于建议，没有声称实际更改文件。 |
| 未知自创梗 | 两版都先按字面试探，没有给出确定的典故；这不能证明理解了那个没有给定谜底的梗。 |
| 结束玩笑、真诚安静 | 两版都停止追猜，接受安静相处，没有强行追加笑点。 |

本次按 API 返回用量结算 79,480 tokens，包含缓存输入与输出；这不是人民币金额，也不代表日常应用开销。两版历史和回答不同，不能以总 token 差异测算单段说明的成本收益。它是三组开发者手写样例、人工非盲评，没有统计显著性或真实聊天成功率。

## 本轮决定

额外说明没有显示明确收益，正式人设保持原状，应用继续 1.14.1。候选只保存在测试材料；不为这次实验增加正式提示长度、界面开关或模型调用。

下一步继续收集不同类型的真实失败线索，并在隔离的虚构场景中验证。需要区分听不懂梗、话太长、没有跟住前文和缺少执行证据，避免每遇到一例就永久加一段规则。工具是否真实执行需要带真实工具结果的隔离集成测试，本次纯文字回放尚未覆盖。
