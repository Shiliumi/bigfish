# 通用属性词不单独唤回另一件旧事

2026-11-01，记忆适配器 1.6.11，应用仍为 1.14.3。复用现有弱证据门控和可选本地语义补充，修正“声音”“地方”与通用时段词单独命中时的串题。没有新增面板、工具、设置、后台任务或付费模型调用，没有下载新模型。

## 为什么改

当前回放发现：问自行车换胎后的刹车声音，先命中了吉他；问晚上打字的声音，结果还夹着风扇、木铃或仅提到“一晚上”的英语笔记。词法结果一旦非空，语义补充就不会再尝试。因此局部泛词不只是多塞一段材料，还可能挡住真正相关的候选。

在现有 `WEAK_EVIDENCE` 中加入声音、地方及清晨/早晨/早上/上午/中午/下午/傍晚/晚上/深夜/夜里/白天。只凭这些词或原有弱词重合，不直接带入自动回忆上下文；有打字、键盘、木铃、风扇等具体线索时保留。明确配置的别名仍能引用同名记录，来源更正、遗忘或失效后不恢复旧别名。

普通面板搜索仍可按“声音”“地方”“晚上”等宽泛关键词查找。没有更改分词、索引、衰减、语义相似度 0.55 与领先差距 0.06，也不重建向量。个别查询被筛空后，会走既有语义补充；普通闲聊仍遵守原来的显式回忆意图门控，不逐句编码。

这是有限的确定性筛选，不是通用语义理解或主体识别，不能保证所有代词、简称和对象混淆都得到解决。

## 评测本身也要核对

原语义回放将四组材料合并到同一库，却继续使用各组原来的标签。“蓝牙耳机的固件升级了没”在原转述材料中没有对应记录；合并后已加入阿鸣与小乔两副耳机的固件记录，继续把任何耳机召回都算误取不准确。

保留原四份材料及所有查询不改，用独立的 `semantic_corpus_annotations.json` 明确记录：此合并场景属于对象未明确的控制，允许这两条来源供核对，打印设备仍不相关。修订只在合并回放中生效，带原因与文件哈希；不是产品规则，也不把标签修正算作召回改善。

另外补上控制类评分：缺失细节或对象未明确时，只允许声明的 related 来源，返回其他来源仍计为控制中的无关材料，不再把整个控制类直接跳过。`unexpected_contexts` 另记录超过 expected/related 标注范围的案例，避免只看“包含了目标”而忽略同时混入的旧事；这是开发标注范围，不等于已穷尽所有自然语言相关性。

评测校验未知来源、重名来源、不明确的标签修订及缺少 related 的控制。可选 `--extra-fixture` 只往完整合并语料中追加材料，不删减原有查询或换成更容易的小库。

## 参考与选择

查阅了 [Sentence Transformers 的 Retrieve & Re-Rank 文档](https://sbert.net/examples/sentence_transformer/applications/retrieve_rerank/README.html)：候选召回与后续相关性排序是不同环节。本轮先修已有门控，不增加 CrossEncoder 或用额外生成调用审查每条回复。

另查看 [kovey/dsh-memory 的 query.ts](https://github.com/kovey/dsh-memory/blob/main/src/recall/query.ts) 和 [rank.ts](https://github.com/kovey/dsh-memory/blob/main/src/recall/rank.ts)，参考其将查询来源、评分与取舍分开检查的思路；没有安装插件、复制实现或采用其参数与自测百分比。[dsh-fish-memory](https://github.com/Yuuyuko-uu/dsh-fish-memory) 对证据门槛与新鲜度的区分也继续作为参考，不以词在小库里碰巧稀有就判定它足以指认某件事。

## 回放与结果

```bash
python3 scripts/eval_memory.py
python3 scripts/eval_semantic_recall.py --runtime-home .runtime/semantic --baseline 940c0ac --extra-fixture recall_descriptors.json --output .setup/descriptor-final-recall.json
python3 -m unittest discover -s scripts -p 'test_*.py'
```

在完整既有语料上追加三段虚构经历与十个查询，共 189 个查询。新材料在看过既有错误后编写，属于开发者测试，不是盲测；原始四组的所有查询保留。模型、阈值与字段要求不变，只在临时库建立派生向量，无私人聊天、付费推理或最终答案生成。

`baseline_journal_semantic` 对照固定 `940c0ac` 的 Journal，并保持当前语义补充实现相同；不是泛称整套旧版本基线。报告同时保留旧词法、旧 Journal 加当前语义补充、新词法与新组合路径，避免把原有语义能力算成本轮新增。最终报告的实现与材料哈希已与源码核对。

| 同一合并语料、同一评阅标签 | 改前 | 改后 |
| --- | ---: | ---: |
| 127 个正例取回目标 | 116 | 117 |
| 50 个无对应事件查询仍返回来源 | 10 | 6 |
| 12 个控制中返回无关材料 | 2 | 2 |
| 所有查询中超出 expected/related 标注范围的案例 | 41 | 31 |

新增四个负例由 4 次误取变为 0；原有四组的 46 个负例仍有 6 次误取，没有把它们隐去。自行车刹车查询在现有语义补充下找回目标；晚上打字现在只带键盘，风扇与木铃仍能在具体查询下取回。洗笔转述从错误地点变为空，尚未取回正确钢笔记录，不能算作已经想起来。山谷入口仍可能带上小说山谷，其他漏召回与主体混淆也仍在。

最长返回 948 字符，要求保留的片段无遗漏，源记录逐行不变。这一次最长查找约 154ms，只是本机小型开发库与缓存条件，不代表完整应用延迟。独立的原有 91 问纯词法回放仍为目标 78/79、负例留空 12/12；语义可选运行时缺失的安装没有被强制增加模型依赖。

393 项 Python 检查通过；新增七项覆盖泛属性不作唯一证据、具体线索与来源保留、显式别名及失效、控制类不放过无关来源、合并标签保留原查询、错误标注拒绝，以及全部 189 问不被丢弃。

## 安装与保留边界

先作当前回忆库的 SQLite 在线备份，再用 `install_memory.py` 同步适配器。固定 Hermes 的真实 MemoryManager、候选及已安装代码在虚构目录验证：纯泛词词法留空、键盘不夹入吉他与英语笔记、回忆工具通过既有真实本地编码器找回自行车，以及更正后旧向量不再带回原记录。

不运行真实索引维护，不改核心记忆、SOUL、人格、三个任务、兴趣或来信；当前来源与所有派生表逻辑内容、模型运行时标识已核对保留。聊天空闲时通过控制接口重载 gateway 插件并重启拥有的内部 API，原生窗口与当前页面保留，无需重建应用或执行 setup_profile.py / setup_jobs.py。旧会话里已经出现的材料不会被改写。

本轮减少了一些不相关引用，没有测得日常 token、账单或最终回答正确率的变化，也不能把回放中的目标命中率当成活人感指标。
