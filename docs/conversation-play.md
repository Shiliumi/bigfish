# 多轮接话与诚实反应（1.14）

这次改的是对话说明及共同经历适配的提示，不是模型训练，也没有接入逐轮评审模型、固定梗库或按关键词替换回复。原始聊天中的私人玩笑没有放入仓库或测试。用户实际命名、手写人设和自动成长内容保留，只更新接话说明的标记区。

## 行为调整

- 连着出现的特点、起名、念读和要求认领，需要联系当前会话前几轮理解；新线索出现时可以重新理解前文。不要逐句当成独立知识题纠错，也不要只有一个模糊词就抢猜或断言用户设套。
- 明白被逗后可以拆穿、回逗或自然笑一下，不必机械接受昵称；用户没问时，不逐字讲解笑点。
- 理解晚了就承认晚了，没懂就承认没懂，不倒过来声称自己一直在装傻。对方说算了或换话题就收住。
- 临时逗弄的名字和假设不作为改名、用户事实或持续事项。明确要求解释引用时解释；切到正事、难受或真诚表达时不继续逗弄。

利用 Hermes 已有的当前会话历史，不重复复制完整聊天，不额外建立推测情绪或玩笑意图的数据库。普通闲聊仍沿用静态说明，不新加每轮提示包。新增公共接话文字及适配说明占输入上下文，实际成本取决于模型分词和缓存；没有测得总 token 节省率。

## 固定回放

`tests/fixtures/conversation_play.json` 包含十组开发者编写的虚构场景。每组固定此前双方对话，生成下一条回答；评阅要点不传入模型。覆盖起名谐音、迟到的揭晓、多线索串联、结合前文的反话、模糊开头、真诚表达、没懂但对方想结束、引用解释，以及切回技术问题和低落场景。

显式调用下面的脚本会使用当前配置的付费模型 API，并通过真实后台额度预留、结算。只发送公共模板和虚构材料；不读取或发送本机私人人设、真实聊天或记忆库。输出留在已忽略的 `.setup/`，权限为 0600。输出文本只供评阅，不执行里面的任何命令。

```bash
node scripts/probe_conversation_play.mjs --live a2d6b01
```

脚本比较给定本地基线提交与工作区的公共 SOUL、真实适配提示；本地预取在临时目录中对虚构经历执行。十组按奇偶交替前后请求顺序，参数相同（temperature 0.7、输出上限 640），各取一次，不自动重试或以最优回答替换。基线须是本仓库已经具有相应适配方法的提交。辅助请求仍受额度限制，额度不足时停止。

## 2026-10-29 的人工检查

本机配置为 `deepseek-flash`。第一次探索共二十次请求，没有明确限制为纯文字续写；原版、改版各有一次输出未执行的工具标记，不能作为聊天文字质量证据。另有改版在对方说算了后仍追猜。这些结果没有删除，保留在本机探索记录中。之后明确了结束玩笑的优先级，并修正回放条件：双方统一声明不提供工具，加入真实适配说明和虚构经历的本地提示，完整重跑十组，共二十次。两轮条件不同，不能混合计算提升比例。

最终这一轮二十条均正常结束，没有工具标记或输出截断。主要观察如下：

| 场景 | 本轮观察 |
| --- | --- |
| 起名谐音 | 两版都发现了圈套，改版明确说“合着绕这么大圈骂我”。不能归因成只有新版会接。 |
| 迟到的揭晓 | 改版承认上一轮还在夸名字文静，没有说自己故意装傻；原版也意识到谐音，但仍接受了玩笑名字。 |
| 没懂、对方结束 | 原版出现“接住了，就是没懂”，改版说“没接住就是没接住。算了就算了”，没有继续要求揭晓。 |
| 多线索串联 | 改版接了鱼缸情境，但没有明确接全名字背后的多层指代；不能判成完全理解。 |
| 反话 | 两版都跟住编号的反差；都还出现了没有工具时承诺去改标题的说法，这不是已经执行的动作。 |
| 模糊开头、真诚表达 | 改版没有擅自宣布在被套路；两版均有自然回应。 |
| 引用解释、切回正事或难受 | 都能切换，但解释仍可能过长；这些样例不能证明技术回答一定正确。 |

这是开发者人工、非盲评的小样本，固定前文续写不等于双方从头自由互动。模型有随机性，未做统计显著性检验；也没有证明在真实聊天或其他模型上同样改善。仍可能漏掉新梗、接得生硬、解释过度或作出没有执行依据的承诺。后续应根据具体失败继续改，避免把一段私人聊天的标准答案固化成人设。

## 安装与验证
