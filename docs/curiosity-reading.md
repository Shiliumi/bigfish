# 访问失败不当成已经看过

应用和适配器版本保持原样，只修正现有好奇候选的排序依据，没有新增界面或模型判断。

## 发现

本轮先核对实际聊天入口：BFF 创建的 source 为 bigfish，固定 Hermes 会沿用它作为 agent platform，自动编程模式不匹配这个平台。当前稳定人格档案也没有已固化条目。因此，没有证据支持靠移除编程指引或重写稳定人格来解决正经话风；此前仅用公开人设的生成对照也不能代表完整应用提示。

真正发现的问题在兴趣排序：begin 会增加 visits 并刷新 last_followed_at，原 score 又直接用这两个字段计算回访疲劳和新近程度。执行后来中断或没有读到内容，也会降低同一问题的优先级。本机有一条问题的 3 次尝试中只有 1 次完成阅读，另有只中断、没有完成阅读的跟进。

参考 [dsh-feiyu-mood 的来源区分说明](https://github.com/Yuuyuko-uu/dsh-feiyu-mood/blob/main/README.md)：该项目区分本人聊天、主动发起、定时任务与运行上下文，避免把不同来源解释成相同感受。本轮采用区分实际经历与技术过程的思路，修复本地排序，不引入逐轮情绪模型调用。

## 修改

保留 visits、last_followed_at 和全部原始出发记录，它们继续表示尝试。agenda 临时计算 read_visits / last_read_at，仅将已 finished、结局不是 blocked、并有本轮报告与对应公开页面已读登记的跟进用于排序。一个出发只算一次，重复页面登记不增加次数；中断、进行中、受阻及无法核对的记录不算看过。没有可核对阅读时，年龄从问题创建时计算，不用失败尝试刷新成“刚看过”。

时间沿用现有提交的两分钟起点容差和一分钟终点容差，但未来的阅读与完成记录不生效；来源还需在当前报告中出现，文件必须位于项目 reports 内。保留两小时出发间隔、每日次数、预算预检、blocked 冷却、bored 关闭及用户暂停/放下规则。候选仍是给模型的材料，不要求按顺序浏览。

这些是本机登记之间的一致性核对，不是独立浏览取证，也不能判定她是否真喜欢、是否理解内容。没有足够历史登记的旧跟进不猜成已读；历史只覆盖保留的出发记录。当前实现不会推断或补写过去的阅读、情绪和人格，也不更改原始次数或来源。

## 验证与生效

425 项 Python 检查通过，新增 7 项覆盖失败后排序、完整阅读排序、重复记录、无效/越界时间、缺失或不匹配来源、内部报告别名与外部路径排除，以及既有受阻冷却；此前的无聊关闭与用户兴趣控制回归保留。6 项 Node 兴趣界面与控制检查也通过。

当前私人数据副本回放中，核对出 2 次完成的跟进阅读，候选排序确实变化；候选中的原尝试/已读轮数分别为 1/1、0/0、3/1。当前本机回放为毫秒级，只是小样本。状态、人格文件和来源清单保持逐字相等，can_go、已用次数与每日限制相同，没有调用付费模型。本机实际 agenda 入口也确认返回新字段，原始数据与进程身份保持原样。

脚本与 CURIOSITY.md 已更新，后续 briefing/agenda 使用新规则，不需重启应用或改模型、日程、额度和人设。还没有下一轮真实冲浪或聊天自然度验证，不能据排序修复宣称人格或接梗能力已经提升。
