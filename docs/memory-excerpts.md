# 记忆节选保留限定条件

2026-10-29，记忆适配器 1.6.4。应用保持 1.14.3，没有新增界面、模型调用、工具或定时任务，私人原话和已保存摘要不改写。

## 具体问题

此前词法召回每隔 180 字找一次匹配窗口，再截取约 280 字。长消息里，“下面只是小说角色的台词，不是我的真实偏好”可能落在窗口外，而窗口内仍有“我最喜欢红茶”。说话人标签虽还在，重要的限定条件却丢了。自动摘要又只是双方原话的固定前缀，不能补全被截掉的语义；在长来源节选时还可能重复携带无关背景。

这次修改的是**如何引用来源**，没有训练模型，也不把这次修复称为通用事实或人格理解。

## 当前做法

- 尽量沿完整句子选择相关片段，常见的中文引号、英文引号、括号和反引号代码范围内不按标点截开；逗号、冒号和分号也不作为断点。相邻语句在预算允许时一并保留，帮助保住后续的改口或条件。
- 普通窗口优先约 560 字；选中的完整语句更长时可以扩展，最终整个词法回忆仍不超过 4,200 字符。放不下的引用不截成吸引人的中段。若某条整段来源过大，跳过该条后仍考虑其他较短来源，不让它把后面的有用记录全部挤掉。
- 词法结果有节选时标记 `excerpted`，原保存过程触及既有长度上限时标记 `source_truncated`。它们是来源完整性提示，不是置信度或用户事实标记。
- 自动摘要与**完整存档原话**核对后去重，不再要求摘要恰好出现在选中的窗口里。自定义更正继续使用当前更正版本，旧原文只供历史核对；摘要本身仍保存在数据库中。
- 来源排名、检索词、显式别名、日期、有效期、更正和遗忘规则保持原路径；原始记录、派生索引版本与向量标识都不改。手动搜索仍可查看未进入自动上下文的原记录。

这是有限的边界规则，不是完整 Markdown/语法解析，更不是否定、指代或跨多句逻辑推理。语义上相隔很远的限定条件仍可能没进入节选；原保存过程已经截掉的内容无法凭空恢复。标记和完整语句也不能保证模型不会误解。可选语义补充继续返回一条完整的当前记法并受自身 4,200 字符上限约束，没有改成词法窗口策略。

## 参考与取舍

[近期 Memoria 社区发布帖](https://www.reddit.com/r/LocalLLaMA/comments/1wyt020/memoria_100_a_local_modelagnostic_memory_system/) 强调本地、模型无关的记忆，并列出多路检索和自己的评测；这里没有复现其成绩，也没有引入整套检索框架。[其 ContextBuilder 公开源码](https://github.com/Kitzkatz/memoria/blob/main/memoria/core/context_builder.py)（所读 blob：`ddbefef92966ee8dab40d58e9db6fa076a1ea250`）按预算选择完整候选，并继续考虑放得下的其他候选。本轮借鉴这个取舍，不复制其代码。

[Anthropic 的 Contextual Retrieval 说明](https://www.anthropic.com/research/contextual-retrieval) 讨论了孤立片段缺少对象、时间等语境的问题。这里只将它作为检查来源上下文的依据，没有采用额外 LLM 生成片段说明或重排模型，也没有把文章中的检索提升数字当作本项目成绩。

```bash
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/eval_memory_excerpts.py --baseline 3fccaeb --output .setup/memory-excerpt-results.json
python3 scripts/eval_semantic_recall.py --runtime-home .runtime/semantic --baseline 3fccaeb --output .setup/semantic-excerpt-results.json
```

第一、二条不访问模型或网络。第三条只使用已经准备好的本地编码环境，在临时虚构库运行正式调用层，不查询私人聊天或远程生成模型。第二条分别建两份临时库，用所选 Git 版本与工作区实现比较；报告保留输入哈希，核对查找前后源记录不变、手动搜索相同、来源限定语确实在返回的 `excerpt` 中，而非碰巧出现在摘要里。

原有材料的上下文字符略降，新增场景总字符由 5,346 到 4,528；更重要的变化是限定语保留。长句为保真可能需要更多字符，这不是供应商 token、日常账单或缓存收益的测量。

274 项 Python 检查通过，覆盖引号、嵌套括号、代码范围、后续纠正、扩展窗口、超预算候选、元数据、摘要去重及源记录保留。安装后的实际适配器还与固定 Hermes 的真实 MemoryManager 在临时虚构目录验证了引用条件和原记录不变，没有向真实聊天注入测试消息。

## 安装

先用 SQLite 在线备份保存运行中的记忆库，再执行：

```bash
python3 scripts/install_memory.py
```

安装器另存旧适配器代码。聊天空闲且无草稿时重载 gateway 插件、重启项目内部接口。无需重新构建应用、重写人设、迁移索引或批量重做向量；不要运行 setup_profile.py 或 setup_jobs.py。加载新版适配器后的新回合使用新的来源节选，已经发过的历史上下文不重写。
