# 记忆整理的文件备份交给本地程序

应用保持 1.14.3，记忆适配器保持 1.6.12，额度适配器保持 1.0.2。现有 review 命令现在完成核心记忆备份，不增加界面、后台任务或模型调用。

## 为什么改这里

参考 [社区关于工具输入膨胀的讨论](https://www.reddit.com/r/hermesagent/comments/1vh8gyp/first_it_was_skills_bloat_now_its_tool_bloat/) 和 [Hermes 核心记忆说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory/)，先在隔离目录实例化当前工具集核对组成，没有照搬帖子中的 token 占比，也没有裁掉浏览工具说明或原话来源。本批 12 条待整理对话各为 36–114 字符，没有长来源读取瓶颈。

现有夜间提示第 2 步要求模型逐字备份 MEMORY.md、USER.md；本机完成过的整理轨迹包含涉及 backups/ 的 terminal 往返。复制文件不需要模型判断，可以合并进本来就要执行的 review，保留模型对事实、偏好和人格的判断。

## 行为

`activity_gate.py review --snapshot ...`（包括单条 episode 读取）在返回本批来源前，先由本地程序保存当时的两个核心文件，并返回 `core_backup` 路径、SHA-256 指纹和创建时间，不返回核心全文。文件按原始字节复制，缺失与空文件分别记录，不创建或修改原核心文件。

备份按快照与内容指纹区分：同一内容重试会核对并复用；核心内容改变时保存新版本，旧版本继续保留。目录一次发布；原文件在复制期间变化会重试，已有备份损坏、路径越出项目或文件过大时失败，不截断、不覆盖。失败时本次 review 不发布新的来源已取出记录。

夜间提示改为采用成功返回的备份回执，不再另跑复制或重复检查备份文件；后续事实核对、原 memory 工具、来源版本检查和提交规则保持原样。专用迁移器仅替换已知的第 2 步，保留用户自定义备份步骤及其他任务选择。

备份是历史版本，不自动恢复，也不随回忆更正或遗忘自动清理。它记录采集时的核心内容，不是跨文件写入锁或断电持久性保证；不限制其他进程之后修改核心文件，也不替代模型对内容的核对。已有历史快照及提交恢复协议继续兼容，没有为旧批次补造备份回执。

## 验证与安装

418 项 Python 检查通过。新增 8 项覆盖逐字节与缺失文件、权限、幂等复用、新旧版本并存、损坏拒绝、复制期间变化、越界与大小限制、回执不含核心全文、备份失败不发布来源覆盖，以及已知/自定义提示迁移。

固定 Hermes 的原生任务库在隔离副本中验证仅第 2 步改变，第二次迁移无操作。当前私人数据副本验证了实际核心文件备份相等、本批来源选择不变、核心文件不变；没有推进真实整理游标或调用付费模型。

本机已执行 `python3 scripts/install_memory_review_sources.py`，复查三个任务的身份、模型、日程及其他字段保持原样；私人 SOUL、核心内容、经历与派生表、人格记录、来信、额度和 gateway 进程也已核对。命令每次由脚本启动，无需重启应用。默认新安装使用更新后的 memory-prompt.txt。

该变更去掉的是提示中由模型执行的备份步骤，尚未测得下一次真实整理的调用数或 token 降幅。新增回执也占少量输入，不能把少一段命令文字等同供应商费用节省。
