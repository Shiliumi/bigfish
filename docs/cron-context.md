# 按任务精简后台上下文

2026-10-29，两个项目后台任务分别使用所需工具；记忆适配器更新为 1.6.2。应用仍为 1.14.2，没有新增界面、定时任务、模型代理或日常评估调用。

## 依据与取舍

[社区的上下文开销讨论](https://www.reddit.com/r/hermesagent/comments/1wco7ab/my_hermes_agent_sends_more_than_140k_tokens_of/) 建议先量固定说明和工具；帖内金额与经验不是本项目证据。[Hermes 官方 cron 文档](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron) 说明任务会使用对应平台的工具集合，也支持任务自己的配置。本轮查看固定版本的 [调度源码](https://github.com/NousResearch/hermes-agent/blob/bf0203a794a07aac3ff764972ab9087baa4e4f4e/cron/scheduler.py) 与离线 prompt-size 实现后，在真实构造的代理上比较。

此前冲浪和记忆整理都继承平台默认工具。改为：

| 项目任务 | 默认工具集合 | 用途 |
| --- | --- | --- |
| fish-surf | terminal、file、browser、web | 本地浏览、公开检索与阅读、保存报告与结构化收尾 |
| fish-memory | terminal、file、memory | 处理增量快照、备份与文件维护、更新核心记忆 |

冲浪阶段的人格观察、未完问题和试行仍由现有本地脚本保存，不需要直接写核心用户档案。夜间整理按原协议处理核心记忆和人格依据，不额外上网。文件工具保留，避免为了缩小工具集合而把所有操作改成更长的终端往返。browser 继续使用配置的浏览器入口别名，保留当前模型无法看图时的文字优先提示。

只迁移仍继承平台默认的两个项目任务；明确填写过的工具组合（包括空列表）保持原样。学习搭子、主聊天、全局工具配置、模型、提示、日程和额度不变。上游仍可能合并用户启用的 MCP 工具，这不是权限沙箱或严格工具总数上限。

## 记忆提示的范围

cron 与子代理已经不提供 `fish_recall`、`fish_correct_memory`、`fish_matters`，但适配器仍返回介绍这些工具的说明。1.6.2 在非主会话不再返回这段 408 字符说明，主会话文字和三个工具保持原样。核心 MEMORY / USER 的加载仍由 Hermes 管理，没有删除人格或用户资料。旧 SOUL 中的通用记忆说明也没有改写，不声称所有身份文字都已按任务拆分。

开发回放的静态说明提取随之兼容函数前面的范围判断；它仍只解析顶层字面量返回值，不执行提供者代码来获取文字。

## 离线量测

```bash
python3 scripts/eval_cron_context.py --output .setup/cron-context-profile-results.json
```

每种任务和变体启动一个新进程，以 dummy 凭据直接构造真实代理，不生成回答。采用当前已安装的 1.6.2，同一份人设、核心资料、工作目录和模型，比较“平台默认”与“任务工具集合”，避免同进程可变注册表影响对照。报告只保存体积、工具名与检查结果，不打印私人人设、原文或凭据。

| 当前代码下的配置 | 工具数 | 系统提示字节 | 工具 schema 字节 | 两项合计 |
| --- | --- | --- | --- | --- |
| 原平台默认，任一任务 | 15 | 35,897 | 24,387 | 60,284 |
| 冲浪专用集合 | 11 | 27,279 | 16,033 | 43,312 |
| 记忆整理专用集合 | 9 | 28,255 | 13,986 | 42,241 |

两项合计分别下降约 28.2% 和 29.9%。构造时检查核心记忆与用户资料内容相同、各任务必需工具仍在、保留工具的参数 schema 相同、冲浪的文字优先提示不变。表格已经包含非主会话说明修正，不把另外移除的 408 字符重复计入工具集合的收益。

这是固定上下文的本机字节量测，不是供应商 token、完整请求体、所有浏览历史或整次任务成本。缓存折扣、任务步数和模型表现会改变实际账单；没有付费生成对比，也未测得日常节省率或任务成功率提升。删去无关工具本身不能保证她接话更自然。

## 安装与维护

```bash
python3 scripts/install_memory.py
python3 scripts/install_job_tools.py --dry-run
python3 scripts/install_job_tools.py
```

工具配置安装器保存 jobs.json 私有备份，只更新两项匹配任务的 enabled_toolsets，并在 Hermes 自己的任务锁内重新检查身份和当前选择；不创建缺失任务，重名拒绝处理。更新后重复执行不重写已存在的明确选择。新安装的 setup_jobs.py 会执行这一步；已有安装使用独立命令，避免为了改工具而重设任务提示或日程。

空闲时重载后台插件及内部接口，无需重建应用或运行 setup_profile.py。新工具组合在后续定时执行使用，正在执行的任务不被强制中断。恢复继承默认可由维护者使用上游任务更新接口将对应 enabled_toolsets 设回 None；也可明确指定自己的组合。备份用于核对字段，运行中的任务库不要整文件覆盖恢复。迁移命令专门处理继承项，设回 None 后再运行它会重新应用项目组合。

诊断与安装命令通过上游安装启动接口选择并租用依赖，避免缓存某一代 bin/python 的路径；仅在命令子进程设置禁止懒安装，不更改全局安装策略。开发诊断曾因旧路径失效而失败，另一次未绑定项目 home 的探索触发了默认依赖准备；没有作为成功量测使用。最终命令固定项目 home、使用安装启动契约并禁止懒安装。上游源码版本保持不变。

258 项 Python 检查通过，覆盖任务作用范围、显式组合与空列表保留、重名、重入、并发时重核选择、非主会话提示范围及回放解析。实际已安装适配器还用固定 Hermes 的 MemoryManager 在临时虚构目录中确认：cron / 子代理无这些不可用说明与工具，主会话保留三项工具。部署前后核对私人设定、模型配置、核心数据、额度、已有流水及学习搭子保持一致；只有两项项目任务的工具字段按计划改变。
