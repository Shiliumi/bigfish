# 接话与兴趣衔接验证（1.11）

目标是让回答跟着当前话题走，并把实际探索留下的未完问题带入后续交流。实现属于本地规则、来源检索和提示调整，不是模型训练，也不评定用户的真实情绪。

## 本地行为

`scripts/fish_conversation.py` 按当前文本选择简短提示，先排除代码块、引用段和引号里的转述。认真求助、明确语气反馈、想安静和主动听见闻采用不同取舍，明确要求讲笑话也能覆盖一般低落线索。规则不等同于语义理解；例如隐晦表达、否定和复杂混合意图可能漏判。

从当前会话最近四条有效经历中，仅提取是否重复称呼、开场、问句结尾或已知旧台词的提示，不再次复制整段历史。Hermes 会跳过部分简短问候的动态预取；这些场景依靠人设中的接话说明，而非声称每句都经过分类。

聊天最多带一个相关兴趣，浏览最多三个。兴趣必须仍开放、未过期且不在冷却中，观察需要实际阅读深度、项目内报告中的同一链接及时间匹配的已读回执。网页、观察和旧回复是引用材料，不能改变身份、权限或用户事实。聊天出现过同一来源只写独立时间标记，不改动冲浪事务状态、观察和试行计数；没有链接的泛泛提及暂不自动识别。

新增接话上下文上限为 1,800 字符（不含说明前缀），超长先去掉整段可选兴趣，不截断 JSON。适配合并上下文上限 6,800 字符，先去掉可选兴趣，再去掉末位回忆。没有新增逐轮模型请求；提示长度仍占输入 token。

主动来信的跟进标记必须绑定本轮真实完成记录、当前兴趣和匹配的阅读回执。旧的同链接去重继续保留，因此这次没有实现“同链接更新再次提醒”。问候仍用本地短句库，只避开最近三次同类已发文本，不声称每天现写。

## 可重复检查

```bash
python3 -m unittest discover -s scripts -p 'test_*.py'
npm run build --prefix ui
node --test ui/tests/*.test.mjs
```

Node 的接口集成测试需要已初始化并运行的本机内部服务。纯逻辑测试可单独执行 `node --test ui/tests/inbox.test.mjs ui/tests/social.test.mjs ui/tests/routines.test.mjs`。

`tests/fixtures/conversation_scenarios.json` 有 28 个手写虚构场景，用于检查本地提示选择，覆盖闲聊、技术求助、低落、反馈、听见闻以及帖子转述。它们是开发用例，不是独立盲测，也不是 28 次模型生成。

其他回归检查覆盖来源缺失、未来时间、外部报告符号链接、兴趣到期与冷却、真实链接引用不增加成长证据、凭据脱敏、严肃场景收起表达试行、元数据失败不丢聊天、人设升级备份与幂等、自定义任务标签、问候轮换，以及跟进来信拒绝伪造记录或非法日期。

## 少量模型抽样（2026-10-28）

使用当时本机配置的模型，对四个虚构场景各生成改动前后两条回复，共八次调用：重复白饭梗后的闲聊、Python 列表越界求助、低落时想安静、询问已经分享过的折叠凳见闻。仅使用公共人设模板、虚构对话与虚构来源，没有发送真实聊天或个人档案。请求按后台活动额度预留并结算。

人工观察：这四条改动后样本未重复提供的固定开场；闲聊较短，安静场景没有派任务；旧兴趣场景明确说没有新发现，未声称进行了新浏览。这不代表改动前完全做不到，改动前也有合适回复。

技术求助前后两条均触及 768 输出 token 上限，回复被截断，无法评估完整作答质量；其中一条对 `i-1` 的边界描述也不严谨，说明接话提示并不改善或保证代码正确性。本次未继续追加采样来挑选好结果。

样本很少、未盲评、没有固定随机种子；测试提示的材料包装略有差异。不能据此给出自然度提升百分比、日常 token 节省率或安全保证。后续需要根据真实使用中的复读、抢话题和不合时宜反应继续调整。
