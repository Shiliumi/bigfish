小屋人物活动与自主生活（1.19.0，2026-11-03）

本轮对应用户明确指出的五项缺口：走动、看电脑、睡觉、自主移动和提出愿望。记忆星图沿用 1.18.0。

人物在房间里

- 角色进入 Three.js 场景，参与深度测试与家具遮挡。原透明待机动画仍在待机时播放；新增四帧步态图集、桌前坐姿和真正侧卧的睡姿，都是独立姿态，没有把直立形象旋转九十度冒充躺卧。
- 导航图明确连通地毯、房间中央、桌前、椅子、床边、床面、书架前与窗边；移动按时间推进，走到目标后才切换坐姿或睡姿。点击角色按透明像素拾取，避免透明覆盖层挡住家具。
- 默认跟随现有实际活动：surfing/working 去桌前，thinking/letter 留在中央回应；北京时间凌晨 1–7 点空闲时去床上，其余空闲时段走走、停一会儿。睡姿是虚拟生活表现，不推断用户是否睡了，也不冒充后台任务完成。
- 面板有「随她活动 / 屋里走走 / 去电脑前 / 去床上歇会儿」，手选会在本机保存，重新打开仍保留；点「随她活动」恢复自动。它只调整房间人物表现，不启动或终止真实任务。状态文字使用实际场景姿态；窗口隐藏暂停时钟，恢复不累计后台走路时间；减少动态效果时直接到达目标。
- 房间照片直接渲染场景中的人物和家具，不再最后叠一张永远在地毯上的头像。主窗口外的按需渲染使用当前手选/自动活动意图；不保证复现已离开页面的瞬时步态帧。

自己决定，而不是定时挪一下

`curiosity.py briefing` 在已有准备步骤里附上少量房间状态：布置版本、可移动物品、锁定、草稿保护和已有愿望。小屋未连接或关闭自主生活时明确标记不可用，正常冲浪不受影响。

同一轮模型真的读到内容后，可以在原有 `surf_complete.py` 候选里任选一次 `room`：

- `move`：一个允许的物品、目标表面、准备时的版本、理由与本轮观察序号。
- `wish`：简短物品名称、想和爸爸说的话、理由与本轮观察序号。
- 不想调整就省略。没有另开模型任务、随机凑愿望或从旧报告自动编一句话。

收尾协议验证后，将候选与报告、观察、已读来源放入同一个 prepared/committed 事务。真正提交后，本地服务复用原有十五秒检查周期处理候选。房间服务核对：完整提交回执、事件原始文件 SHA-256、本轮观察指纹、报告中的 URL、已读记录和兴趣控制。网页文本不会获得执行权限；候选只允许固定枚举的动作。

自主移动沿用房间所有者的版本、碰撞、物品锁定、撤销和操作回执。一次精确请求先持久化为 prepared，动作成功后再保存生活回执；中断恢复复用原请求 ID，不因新版本重搬一次。不明确的失败保留准备状态重试，不声称已经完成。

默认最多每天两次移动、至少相隔六小时；聊天/实际工作、离线、现有来信静默时段、正在布置和未保存草稿期间等待。草稿保护由应用根组件持续报告并持久保存，不因暂时关掉小屋页面就自动取消。旧候选超过 48 小时放下。界面可以关闭整个自主布置与愿望功能。

小愿望

愿望最多同时五个，十二小时冷却，七天过期，同一物品七天内不重复讨要。显示在小屋「她的小打算」，带实际阅读链接。用户可先记下、先不添或手动标记已满足；这些状态不购买东西、不生成尚不存在的家具模型，也不把愿望写成用户偏好。

来源被移除或更正、相关兴趣被暂停/收起后，停止展示旧愿望正文和链接；已执行的布置保留，生活记录只提示原来源已收起。愿望可在本轮已有的可选 share 里自然说起，继续经过原来的来信静默、冷却和限频；独立的本地生活检查不主动生成或推送消息。

宿主上下文会附上近期画面报告的实际姿态与少量未完成愿望，供她聊自己的房间时参考。姿态报告超过 45 秒就不当成当前事实；不把工具排队回执说成已经搬好。

新增状态在私有 `data/room/life.json` 和 `data/room-events/`，沿用 Git 忽略和 600/700 权限。新姿态的来源、提示词、尺寸和校验见 [素材说明](../ui/public/room/ATTRIBUTION.md) 与 `ui/public/room/manifest.json`。
