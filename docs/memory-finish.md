# 夜间整理完成后及时收尾

2026-10-31。根据本机实际执行记录调整原有任务协议，没有新增界面、任务、工具或模型调用。应用保持 1.14.3，适配器保持 1.6.8。

## 先看实际开销

2026-10-30 的后台主请求计数为 1,782,930 tokens，包含约 93% 缓存输入；开发用的对话回放单独记账，不混作正常任务消耗。该计数不是未缓存输入量或账单金额，不能据此直接估算价格。

其中一次夜间整理为 15 次模型请求、408,354 tokens，执行了 23 次工具调用。报告阅读、来源读取、人格反馈与核心记忆写入有实际用途，不应为了少调用而跳过。前一轮完整来源协议也在本次运行中成功取出并提交了本批 12 条对话来源；这证明实际链路跑通，不证明模型读懂每条来源或误记率下降。

明确的冗余在成功 commit 之后：模型又发起四次 terminal 操作，继续核对 trials.json / profile.json。其中两次分别尝试解释器 heredoc 与 `-c` 内联脚本，被固定 Hermes 的现有 cron 审批规则拦下，随后才换回可用方法和现有 `personality.py trials`。本批此前已经提交成功，这些不是提交所必需的失败重试。

因此本轮没有减少需要审阅的来源、调低采样参数、替换模型或扩大审批，而是把人格变更核对放到正确阶段，并明确成功返回后的终点。

## 调整后的顺序

原有来源读取、备份、人格证据要求、报告和提交接口保留，只更新任务提示的第 3、5 步：

1. 有相关新增经历时，按原协议读取 `python3 scripts/personality.py trials`，再决定是否需要反馈、晋升或撤回。
2. 若确实执行过 feedback / apply / retire，全部完成后，用同一 trials 命令核对一次最新状态，再写报告；没有变更不重复查。无需为读现有状态自编 Python，也不要求每批都修改人格。
3. 保存报告，按原命令 commit。本批返回 `ok=true`（含已经完成的幂等结果）后直接结束，不继续自检、不在提交后追加人格反馈。剩余来源留给后续批次。

失败仍按原协议处理，不自行修改游标。此次没有修改 commit 的校验和持久化实现，也没有增加强制中断模型的运行时规则；提示能否让后续任务少走冗余步骤，需要继续观察真实执行。

## 参考与保留边界

[官方 cron 说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/cron) 介绍了原生任务编辑与执行方式。本轮仍通过该固定版本的原生任务锁和保存接口更新既有任务，不另建调度器，不变更模型 pin、日程、工具集、其他步骤或学习搭子。在线文档可能领先于固定源码，以本机实际分类和执行结果为准。

本次查阅聚焦官方开源实现和本机轨迹，没有用论坛中的泛化“省 token”建议代替实际瓶颈。完整轨迹保留本地，只记录汇总与公共命令，不发布私人聊天、观察内容或凭据。
