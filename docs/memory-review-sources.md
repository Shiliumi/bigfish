# 夜间整理先核对完整已存来源

2026-10-30。应用保持 1.14.3，记忆适配器保持 1.6.6。本轮更新已有夜间任务的来源读取和提交检查，没有增加界面、任务、模型服务或每条聊天的额外推理。

## 确认的问题

聊天回忆已有保留限定条件的节选，但 `activity_gate.py review` 仍把每段对话的自动摘要交给整理任务：用户前 160 字与鱼前 200 字拼接。这样的前缀可能留下“我喜欢……”而丢掉后面的“这是举例，不是我的偏好”，也可能丢掉鱼补充的“只是猜测，尚未确认”。它不是一次经过核对的事实提取。

改动针对这个确切入口，不重建回忆库，不自动重写已经整理过的核心记忆，也不据此声称已经发现实际错误事实。

## 当前协议

运行原来的命令：

```bash
python3 scripts/activity_gate.py review --snapshot 实际快照编号
```

- 普通对话返回完整的**已存**文本，带来源、记录时间、revision 和版本有效期；不再提供容易误解的自动前缀摘要。
- 更正记录只返回当前更正文案和更正来源，不把已经替代的原始说法重新提供为当前依据。
- `source_parts` 按顺序拼接等于完整已存文本，没有挑选片段或省略中间内容。每段至多 250 字符，CLI 输出格式化 JSON；即使终端把大输出保存到文件，来源内容也能避开固定 Hermes 默认的每行 2,000 字符读取上限。文本里的角色标签仍是引用文本，不能变成当前消息身份或授权。
- 对话内容的内联预算为 6,000 个紧凑 JSON 字符，按整条记录决定是否加入。放不下的记录返回 `read_required=true` 和读取该条的完整命令，不截断；后面较短的记录仍可加入。该预算不是整个返回包、UTF-8 字节或供应商 token 的上限，其他来源与格式化空白另计。
- `source_truncated=true` 提醒当初采集可能已不完整；目前采集边界仍为用户 4,000、助手 6,000 字符，不能通过此次读取恢复已经没有存下的部分。举例、玩笑、假设和未确认的内容不能据此前缀升级为用户事实。版本有效期也不是所述事件发生的日期。

长记录的命令形如：

```bash
python3 scripts/activity_gate.py review --snapshot 实际快照编号 --episode 本批实际ep编号
```

只能读取本快照选择的记录，不能拿另一个 ep 编号扩展本批。来源已经更正、遗忘、过期或变成未来版本时会拒绝返回。凭据在交付时再次隐藏，包括采集后才配置为密钥的字符串。

快照会记录哪些对话版本已经由读取接口取出，**这只证明接口已构建该版本的完整来源包，不证明终端显示无截断、模型理解、实际读完工具保存的文件或判断正确**。整包构建失败时不记录新增交付；CLI 沿用已有跨进程锁。提交仍要求报告标记、全部来源版本一致，并新增核对本批所有对话的交付覆盖。大记录尚未取出时提交失败、游标不推进，也不会把它从本批移走。旧的未提交快照同样需要先取得来源；已经提交的批次保持幂等，不补扫历史。

工具输出若被截断，任务提示要求继续读取工具保存的完整文件，不把未展示内容当作已核对。这个要求仍需要模型遵守，交付检查不能替代事实核实。reports、observations、preference_events 的现有读取范围和每类最多 12 项的批次规模保留，remaining 继续留给后续机会，不无限清空积压。

[Hindsight 的整理设计文章](https://github.com/vectorize-io/hindsight/blob/main/hindsight-docs/blog/2026-05-21-agent-memory-consolidation.md)（所读 blob `9f8a6fcf7e2e2db1d16fc3b85e003041da90e9d2`）讨论写入取舍与来源、时效冲突，帮助区分“检索到内容”和“内容适合保留”。没有采用文中的产品排名或性能数字作为本项目依据。

## 验证和成本

```bash
python3 -m unittest discover -s scripts -p 'test_*.py'
```

316 项通过。新增 16 项检查覆盖后置限定、当前更正、采集不全标记、长记录整条延后、小记录继续进入、缺交付拒绝提交、旧快照、新增与不在批中的来源、版本变化、遗忘/过期/未来状态、后配密钥隐藏、整包失败、实际 CLI 的无损拼接与默认行上限，以及任务迁移的保留与竞争保护。

在当前待整理数据的隔离副本中，对照 `50b42e5` 与新版：本批 12 条短对话均一次内联返回，逐条拼接与当前库文本一致，没有请求额外来源。返回包从旧版约 8,000 字符增加到新版约 12,200 字符（新版计格式化空白），UTF-8 约 17.5 KB，低于本机 Hermes 配置的 50,000 字节终端上限。这里的长度来自一个真实批次的本地副本，不是 token 数或节省率；保留完整来源会增加整理输入，大记录还可能多一次本地读取。没有运行付费模型整理，也没有推进实际游标或插入测试聊天，尚未测得实际整理误记率变化。

固定 Hermes 的原生任务库在临时副本验证了只修改已知入口步骤、重复安装不修改、三个任务及其其他字段保留；审批分类器确认两种直接 CLI 命令不属于其危险命令规则，这只是分类检查，不是代用户批准执行或改变其他审批策略。本机迁移后的核对也确认：仅任务入口提示与原生库保存时间变化；私人配置、核心记忆、成长、兴趣、来信、游标和记忆/额度数据保留，未重启 gateway 或应用。
