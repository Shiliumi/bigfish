小屋布置与照片（1.16.0）

实施日期：2026-11-02。此版本完成手动布置和房间照片核心流程，自主房间行动尚未接入。

使用方式

- 在“她的小屋”选择“布置小屋”，拖动杯子、书或抱枕。也可以选中物品，在介绍面板里选择放置区域、转 90°。大件家具暂时固定。
- 物品必须放在允许的区域，不能与同一表面的物品或固定障碍相撞；无效落点放回原位。保存后可连续撤销历史布置（最多 12 次），恢复默认也可以撤销。
- 未保存的布置草稿留在当前应用的本机存储中。切页或重启后会恢复；另一窗口已保存时会拒绝覆盖，用户可明确选择“读取已保存布置”。
- 保存布置后，可拍“全景”或“窗边”，在最近照片相册里重新打开。“带到聊天”把照片放进输入框，保留原有文字，点击发送才调用现有聊天。
- 普通滚轮用于滚动页面；⌘/Ctrl + 滚轮或场景下方加减按钮用于缩放。

数据与一致性

布局、历史、请求回执和照片清单保存到私有 `data/room/state.json`；照片单独保存为 PNG，目录与文件分别限制为 700/600。目录沿用仓库忽略规则，不提交照片或布置。服务内串行处理修改，JSON 临时写入后原子替换；部署约定仍是单个本地 UI 服务。

布局采用单调递增版本，过期保存、撤销与拍照返回冲突，不覆盖最新布局。相同请求 ID、相同内容的重试复用回执；变更内容会被拒绝。损坏存档保持原文件并明确报错，不自动回退到默认布局覆盖原件。

拍照使用当前渲染器的独立固定视角，只包含房间和角色。捕获中保持 CSS 尺寸不变，并在浏览器绘制前恢复实时帧；没有读取桌面、其他窗口或聊天内容。保存前校验布局版本、PNG CRC、像素尺寸、解压大小和有效滤波编码，剥离附加元数据。图片接口继承桌面鉴权、同源与修改请求保护。

照片带有拍摄时间、布局版本、视角与氛围说明。当前聊天沿用文本模型：图片在对话中展示，并附带结构化布局说明；这不代表模型获得视觉能力，也不会自动使用第三方识图服务。照片、文字草稿可随应用重启恢复，发送失败时保留待发内容。

成本与更新

布置、拍照、查看相册、昼夜与天气均在本机执行，没有新增模型请求。只有用户发送消息才走原有模型流程。此版本没有新建定时模型任务，也没有更改原有冲浪任务、记忆或人设。

生产构建保留已有哈希资源，避免打开着的旧页面在更新后再加载功能时出现资源丢失。已有资源目前不会自动清理，仅占用被 Git 忽略的本机 `ui/dist` 空间；这项修复不等于所有白屏原因都已完成验收。

实际验证

- 81 项 Node 测试通过，覆盖布局重启恢复、并发冲突、请求幂等、撤销/恢复默认、放置碰撞、照片版本一致性、损坏存档保留、PNG 校验及接口鉴权。TypeScript 和生产构建通过。
- 隔离测试使用实际组件、样式和临时房间服务，不访问用户聊天或模型。实测家具拖放、无效落点还原、床上同时放书与抱枕、保存后重新加载、撤销、全景/窗边照片、弹窗关闭与普通滚轮滚动。
- 520×420 窗口检查了照片预览、关闭按钮和滚动区域；模拟图形上下文丢失后恢复。
- 在实际 macOS WKWebView 拍照并带入聊天草稿，确认等待手动发送。退出并重新启动已安装应用后，照片附件与测试文字草稿仍在；测试内容已移除，没有向模型发送验收消息。

仍需后续验收或实现

- 尚未完成连续 1 小时后台、真实系统休眠/唤醒、完整中文输入法组合和帧率/资源基线测量；短时和模拟恢复不能替代这些测试。
- 相册展示最近 24 张，旧照片仍保留本机；照片清理/回收站、导出入口、独立照片磁盘配额尚未实现。
- 目前电脑、本子等物品导航到现有探索和记忆页面，尚无物品内部的最近阅读卡片。
- 用户锁定物品、模型移动家具、主动自拍、兴趣愿望和共同纪念物留待下一阶段，不能仅凭聊天文本声称已执行房间动作。

复查：先运行本地服务，再运行 `node --test ui/tests/*.test.mjs` 和 `npm --prefix ui run build`。隔离交互服务：`node ui/tests/room-browser-fixture.mjs`，访问输出的本地地址；退出后清理其自建临时数据。
