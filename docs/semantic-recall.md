# 可选本地语义回忆接入

2026-10-29，记忆适配器 1.6.0 将此前的 [隔离实验](semantic-memory-study.md)、[同库缓存](semantic-cache-transactions.md) 和 [项目运行时](semantic-runtime.md) 接入现有共同经历回忆入口。应用仍为 1.14.2，无需重建应用，也不增加面板、工具或定时任务。默认安装不下载模型；没有显式准备可选运行时的项目继续使用词法检索。

## 行为与边界

先运行原有词法回忆。已有结果原样返回；只有没有结果时，才考虑本地语义候选。手动 `fish_recall` 可以使用补充；自动预取只对“还记得”“之前聊过”等明确回忆意图启用，普通闲聊不逐句编码。

- 检查明确的书名、有限的两字昵称提示、数字或版本号，避免另一对象的相似经历混入。类别内允许多个目标，类别间共同约束。用户设置的别名仍有效；这些规则不是通用实体识别或关系推理。
- 简单的“不是甲，我问的是乙”只将后半句用于检索，不改写任何来源。无法明确消解的排除条件、稳定偏好和敏感精确值问题不走语义补充；合同、采购等交易的金额或状态问题仍沿用现有检索与事项。
- 只接受当前有效、非当前会话且符合日期和对象范围的来源。所有范围内候选都须有完整、当前版本的向量，避免漏索引竞争者造成虚假的领先差距；排序后再次检查来源版本、有效期与覆盖情况。
- 保留既有 0.55 相似度、0.06 前两名差距门槛，未重新挑选。一次最多补充一条完整当前记法，保留说话人和否定；连同来源说明超过 4,200 字符就留空，不截掉限定语。返回的是旧对话引用，不是已确认的用户事实，也不证明问题所问的细节存在。
- 可选运行时、索引或编码不可用，锁繁忙，来源改变，或超过检查期限时退回词法路径。编码子进程默认期限 2 秒，调用层另有 2.5 秒检查期限；这不等于操作系统启动和清理在内的严格端到端期限。超过 2,000 条活动记录时暂不进行语义补充。

真人聊天完成后，在既有异步保存路径中，优先为该条来源补索引，每次最多两条、预算 3 秒。来源成功保存后编码失败不会撤销聊天；未完成来源本身就是下次重试队列。自动消息、cron 和子代理不通过这条路径建立共同聊天索引。查询时不临时编码整个历史库。

向量写在原记忆库的派生表中，更正和遗忘与向量失效一起提交；到期来源读取时排除并清理。它不改变原始聊天、核心档案或成长记录，不意味着删除备份或供应商数据。模型只在本机编码，没有新增付费模型调用；本地 CPU、内存、磁盘仍有成本，尚无日常 token 节省率测量。

## 参考与开发回放

[Google Research 的 QUEST 论文介绍](https://research.google/pubs/quest-a-retrieval-dataset-of-entity-seeking-queries-with-implicit-set-operations/) 将实体查询中的组合与否定列为检索难点。本轮据此补充对象约束测试，没有运行 QUEST 基准。[社区关于记忆纠错和重复记录的讨论](https://www.reddit.com/r/Rag/comments/1urskg6/your_agent_memory_probably_cant_tell_a/) 用于提出来源与身份检查问题，不将帖内自测当作本项目证据。

四份虚构材料合并到临时库，179 个查询用真实本地模型、限时进程及正式调用层回放。对照提交 `2122ff3`，固定既有门槛。表中正例为取回目标来源，负例为没有对应经历却仍返回来源的次数；不是生成答案正确率。

无需模型的全部 Python 检查 235 项通过，覆盖覆盖率、来源并发变化和到期、损坏向量竞争者、锁与进程失败、原文脱敏、纠错失效和自动消息排除。还在临时虚构库中，用已安装适配器及固定版本 Hermes 的真实 `MemoryManager` 验证异步索引、工具召回、自动预取、失败降级和纠错。没有向真实聊天插入测试消息或调用付费生成模型。

## 安装与维护

先显式按 [运行时说明](semantic-runtime.md#显式准备) 准备模型和项目内 Python，再安装适配器。已有安装不要运行 `setup_profile.py`，以免重新生成私人设定。

```bash
python3 scripts/install_memory.py
python3 scripts/semantic_maintenance.py --seconds 30
python3 scripts/semantic_maintenance.py --check
```

维护命令只打印数量，不输出真实聊天；未完成返回非零，下次可继续。`--check` 检查覆盖情况，但可能初始化或修复派生 schema，不能当作严格只读命令。先用 SQLite 在线备份保存运行中的记忆库，适配器安装器另外保留旧代码备份。聊天空闲时重载 gateway 插件、重启内部接口；不需要重设模型、人设或日常任务。安装代码不自动批量编码旧聊天，以上维护命令是明确的本地历史索引步骤。

本机已备份并安装 1.6.0，29 条当前有效来源完成本地索引，内部接口和 gateway 已加载；应用在线。逐项核对更新前既有经历、历史、事项和事项事件保持一致，原库版本、私人设定、模型配置与日常任务定义保留，gateway 原进程继续运行。这个数量只是部署时快照，不作为其他机器的预期值。

需要停用语义补充时，将 `.runtime/semantic/active.json` 改名保留，再执行 `--check` 会提示运行时不可用，回忆继续走词法路径；恢复文件即可重新启用。无需删向量或原始记忆。若确需移除派生缓存，用 `fish_semantic_cache.discard_cache(journal)` 在备份后清理自己的表和触发器，**不要删除 `episodes.sqlite3`**。历史缓存文档仅用于理解当时实验，当前部署以本页为准。
