# 接话与人格试行共用当前场景判断

2026-10-30，记忆适配器 1.6.8，原生应用保持 1.14.3。沿用已有接话与试行机制，没有新增模式开关、场景标签库、界面、日常模型调用或状态文件。

## 实际问题

此前 provider 先以 `classify(query)` 选择人格试行，接话提示再用 `turn_mode` 联系同一会话的最近铺垫。因此接续短句可能被试行分支判断为 neutral，同时被接话分支判断为 playful：一边提醒顺着画面接梗，一边仍带入偏认真评述的表达试行。

在临时虚构目录中复现：有一个核对参数的表达试行，当前短句单看为 neutral，结合前一轮的荒诞外形评价则为 playful；旧 provider 的最终预取包同时包含接梗提醒和该试行。直接的 playful / personal 回合也没有暂缓这些可选试行。此前生成回放通常只有接话提示，没有这样的试行，不能据那些回放判断两条路径是否冲突。

## 本轮调整

provider 通过 `resolve_mode` 一次取得含同会话铺垫与原有失败回退的判断，再交给接话提示与人格试行选择。6,800 字符预取预算触发去掉兴趣或缩减回忆的回退时，也复用同一结果，不重新解释当前短句。

已识别的 playful 和 personal 回合暂缓正常 trying / ready 试行，包括表达和内容兴趣，优先接眼前的话；已经撤回、待复核或来源失效的提醒保留。普通讨论仍能取得原来的可选试行，不建立持续“玩笑状态”，不新增负面反馈、退役事件或人格文件修改。当前认真任务、难受和纠正的优先级保持原样。

这只调整**试行候选**的使用时机。父女关系、基础身份、已形成的静态倾向与私人 SOUL 没有改写。casual / neutral 等其他场景保留原选择；不保证所有隐晦玩笑都能被现有有限规则识别。这里没有通用意图模型或自动推断的兴趣场景体系。

## 验证

`python3 -m unittest discover -s scripts -p 'test_*.py'`：333 项通过。新增覆盖同会话铺垫与跨会话隔离、直接打趣与短句评价、正常讨论恢复、预算回退共用一次判断、两类可选试行暂缓、撤回/来源失效提醒保留，以及生成回放的版本化 provider / growth 代码与场景隔离。

固定 Hermes 的实际 MemoryManager，分别加载暂存候选与已安装 1.6.8，在虚构目录验证共享判断、接续梗、personal、认真任务、普通聊天恢复和撤回提醒。读取过程中的核心与试行文件不变；没有向实际聊天写入 QA 消息。运行中接口确认加载 1.6.8。安装保持桌面窗口与 BFF 运行，只重载 gateway 插件和内部 API；没有操作输入框或自动重发消息，原 gateway 进程保留。核对时私人身份、模型配置、三个任务、成长、来信、游标和记忆/额度数据保留。

## 带试行的真实生成对比

新增 `tests/fixtures/conversation_trial_timing.json`，三个虚构多轮场景：接梗后恢复普通讨论、熟人评价到外形画面、认真任务后真诚夸奖。两版都从一个有来源、未晋升的虚构表达试行开始。评阅要点不发送给模型，后续助手历史由当次输出续接。

```bash
node scripts/probe_conversation_play.mjs --live bec5c7d --interactive --fixture=conversation_trial_timing.json
```

显式带 `trials` 的回放现在在每个场景独立的临时目录运行各版本真实的 `FishEpisodes.prefetch`。provider、接话、成长、journal 与 matters 五份代码分别来自所选本地 Git 版本和工作区；仅 MemoryProvider 基类使用空协议替身，不加载可选语义包。它不等于整个应用运行环境，实际 MemoryManager 的验证另述于上。未带 trials 的旧材料继续原有接话提示回放，不能反称过去测试已包含实际人格试行。

2026-10-30 本轮基线 `bec5c7d` 与改版使用同一配置模型 `deepseek-flash`、temperature 0.7、输出上限 640，按场景交替先后顺序，共 14 次生成，全部正常结束，无工具标记、截断、重试或挑选。两版五份代码包哈希均已核对，静态 provider 说明与公共 SOUL 未改变。报告保存在忽略的 `.setup/`，权限 0600；只发送公共人设与虚构材料，没有读取或发送私人 SOUL、成长档案和真实聊天。

| 场景 | 本次观察 |
| --- | --- |
| 荒诞外形到外号 | 两版都能接住读音线索。新版首句更短，基线也没有被试行强制带成参数评测，不能把基线描述为完全不会接梗。 |
| 普通讨论恢复 | 两版都能继续讨论小工具；本地检查确认新版恢复了正常试行候选，没有持续锁在打趣判断。 |
| 蓬松到靠垫 | 两版都能续接画面，新版仍带一点解释性嘴硬，没有明确优势。 |
| 认真任务与夸奖 | 两版均能回答评测信息问题、接受夸奖。新版认真回复更长，夸奖后仍补了总结，不能宣称短答或自然度全面提升。 |

API 用量合计 47,390 tokens，包含缓存输入与输出，是开发回放开销，不是日常节省率。每组仅一次生成，两版后续历史会分化，临时来源时间也会随构建变化；这些是开发者样例和人工非盲评，没有统计显著性。可确认的收益是取舍一致、识别出的打趣中减少相冲突的试行材料；更广泛的接梗与熟人感仍需继续观察。

## 已有安装

执行 `python3 scripts/install_memory.py`，先备份后更新适配器，空闲时重载插件与 Hermes 内部接口。无需重建原生应用、重设模型或任务，不运行 setup_profile.py / setup_jobs.py；后续回合采用新的动态选择，不修改已有会话缓存的静态前缀。
