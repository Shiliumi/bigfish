小屋阶段 2 补齐（1.17.0，2026-11-03）

这次对应原实施计划第 2 阶段的物品内容卡片和照片生命周期管理。阶段 0/1 的专项验收、阶段 3 的自主生活和共同记忆、阶段 4 的纪念物与关联展示仍未全部完成。

物品中的真实内容

- 点书桌查看最近六条可核对的网页正文/评论阅读记录。候选必须同时有正文观察、匹配的浏览记录和包含该链接的真实报告；搜索摘要不充当已读正文，页面正文已读也不代表看完视频。
- 可以收藏或取消收藏网页，最多 50 条。收藏文件只保存来源引用，不复制一份观察正文。每次打开或刷新重新核对来源；旧收藏离开近期窗口后会按 URL 流式补查，来源变化时缓存失效，不因翻出近期列表就当成丢失。
- 点本子或书架查看近期/已固定的三条当前有效共同经历，可展开现有回忆的当前记法、来源编号和历史核对片段，也可以打开原记忆空间继续更正或遗忘。不另外生成回忆、不把旧原文冒充更正后的事实。
- 只有物品面板打开时读取卡片，页面可见时每十秒刷新；收到记忆修改事件会清除已展开来源并重新读取。无来源、已过时、已遗忘与服务故障分别处理，不填充示例经历。布置模式优先显示移动控件，避免长卡片挤占拖放操作。

相册管理

- 最近相册保留简洁缩略图，管理界面按每页 24 张查看全部照片和回收站，显示实际文件用量。默认上限 200 MiB / 500 张，含回收站，满额时明确拒绝新照片而不静默删除旧图。
- 移入回收站和恢复都使用相册独立版本，不影响布局版本或撤销历史。回收站期间保留原聊天的图片引用。
- 永久删除只针对已在回收站的照片；应用内先展示明确说明，再由用户点击确认，服务端同时校验确认字段、当前版本和操作 ID。没有自动按时间清空回收站。
- 删除先将原图移入私有暂存区，再原子提交清单；提交失败恢复原图，中断后根据已提交清单恢复或完成清理。永久删除保留不含图片、标题或布局正文的墓碑，旧拍照请求不能重新创建同一照片。
- 新照片的清单写入失败时回滚刚生成的文件。对于突然掉电等未完成事务，不承诺跨文件系统的持久化事务保证。
- 原生应用使用 macOS 保存窗口导出 PNG，固定本机下载接口和照片 ID，不接受任意文件路径。清理相册文件不删除原聊天文本、之前导出的副本或其他客户端已经加载的缓存；后续图片请求会明确失败。

存储与运行

使用原有私有 `data/room/`：布局和照片清单仍在 `state.json`，收藏引用在 `collection.json`，删除暂存区是 `.purge/`。文件和目录沿用 600/700 权限与 Git 忽略规则。读取卡片、收藏、相册管理、导出都不调用模型；本轮没有修改人设、模型、记忆适配器、任务或后台 gateway。

验证

- 101 项 Node 检查与 TypeScript/生产构建通过，原生应用编译、安装为 1.17.0 / build 24。
- 新增测试覆盖阅读交叉核对、只投影有效记忆、来源更正/丢失、旧收藏补查、收藏冲突、回收站重启恢复、永久删除确认、额度、旧请求墓碑、删除中断和存档失败时原图恢复。
- 隔离界面验证收藏、回忆来源、520×420 小窗口、回收站、取消永久删除、恢复和 PNG 下载。永久删除及故障注入只对测试创建的临时目录运行；没有移动、删除或收藏用户真实资料。
- 真实原生应用显示已有阅读和共同经历；通过 macOS 保存窗口导出一张验收照片，文件与原 PNG 逐字节一致。关闭主窗口后仍成功按需渲染新照片，再打开窗口时未保存的布置草稿仍在。该检查不等于完成一小时后台或真实系统休眠验收。
