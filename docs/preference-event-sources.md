# 人格历史事件也要核对来源版本

2026-10-31。完善项目自己的记忆整理与人格 CLI，应用保持 1.14.3、适配器保持 1.6.10。不增加面板、后台任务或付费判断调用，不自动删改 SOUL 的稳定倾向。

## 发现与复现

稳定倾向和未晋升试行已经核对当前来源，但人格事件还是另一条输入路径。虚构试行的唯一支持被遗忘后，聊天上下文会暂停该试行，夜间 `review` 却仍返回旧 started 事件的原措辞和理由。`trials` 的原始变化历史，以及 feedback 返回的完整旧 signals，也可能再次带回这些文字。

这是隔离复现，不宣称实际发生过某次误记。自动整理需要知道曾有变更，不代表需要把失效依据的原表述重新拿来当当前材料。

## 新的处理

新建 started、反馈及 blocked 事件时，保存该次操作实际核对的来源编号和意义指纹，写入 `evidence_version=1`。它们不是额外经历，也不增加晋升计数。原试行与反馈函数的内部结果不变，独立来源、跨日期、三天观察期和反例冷却条件保留。

自动 `review` 核对两层：事件本身仍匹配当前快照版本，事件所绑定的来源也仍有效且指纹相符。符合时才返回其历史措辞与理由，并标明 `source_state=verified`；这不代表当时理解正确，不能把鱼的倾向当用户偏好。

来源更正、遗忘、到期、未来生效、报告不可核对或版本不符时，只返回变更编号、试行编号、revision、动作、时间与通用说明。旧格式事件没有独立来源版本，不从当前 signals 反推它当时依赖哪条来源，也只提供元数据。没有来源绑定的撤回仍保留 retired 动作，不靠旧措辞恢复内容。unbound 不是负面反馈，不自动重开或撤回试行；当前试行是否有支持仍按原有信号判断。原始记录保存在本机，没有迁移、伪造旧证明或清空历史。

`review` 将实际生成的事件视图指纹保存在原快照的 `delivered_preference_events` 中。commit 前重新核对：即使事件文件没变，只要依赖来源的变化导致视图改变，也不能按旧视图完成提交；须重新读取同一 review 并核对报告。旧快照若没有这些交付记录，也要先按原命令读完整批次。全部结果构建成功后才保存交付记录，不把生成了一半的 payload 当作已返回。与对话来源一样，这只证明生成过来源包，不证明模型阅读、理解或报告正确。

## 自动命令与人工历史分别保留

现有后台任务本来就使用 `personality.py trials`，因此同步修正这条命令，避免只过滤第一步、后面又从历史读回来：

- `trials` 返回当前试行与经过来源核对的事件历史。无当前正面支持的条目不返回旧 text；缺少有效事件绑定的旧理由也不自动返回。仍有其他真实支持的试行保留其当前措辞，不一概撤回。
- CLI 的 `trial`、`feedback` 成功只回传 ok、编号、kind、status、revision 和可选 already_recorded；`apply` 成功只回传 ok、profile revision、updated_ids。不再回传整份旧 signals 或完整 profile。内部 Python 函数契约与持久化结果保持原样。
- 应用使用的 `api`、明确人工查看的 `status` 和原始档案保持完整；界面中的原试行与变化历史仍可查看、核对和主动放下。没有删除用户手写身份或自动编辑 USER.md。

本仓库的调用点已核对：原生界面通过 `api` 读取，完整冲浪收尾直接调用内部函数并已返回精简回执，自动整理使用上述 CLI。依赖旧 CLI 完整 JSON 的外部脚本需调整；人工查看完整档案可继续用 status。原任务“实际变更核对后、commit 成功即结束”的顺序不变，没有新增模型步骤。

## 参考与边界

[dsh-fish-memory v1.3.6 发布记录](https://github.com/Yuuyuko-uu/dsh-fish-memory/releases/tag/v1.3.6) 与 [其合并源码](https://github.com/Yuuyuko-uu/dsh-fish-memory/blob/main/lib/store-merge.mjs) 处理了旧快照写回与删除交错的问题；另查看了其 purge-generation 故障测试。这里借鉴“旧材料不能凭旧快照重新取得当前资格”的原则，没有复制实现或引入第二套存储。

[Hermes 历史问题 #26045](https://github.com/NousResearch/hermes-agent/issues/26045) 讨论外部写入与内存快照不同步，当前已关闭；本轮不据此认定固定版本仍有该故障，也没有修改原生 memory 工具。自动视图只负责选材，保留数据与身份边界。

这仍不是完整级联遗忘或物理擦除：历史界面、人工 status、原始事件与备份保留，已载入会话的静态 SOUL 和聊天历史不会被改写。稳定倾向仍走现有复核及 retire 流程。模型主动读取其他完整档案时，仍须遵守来源与纠正协议；没有把输出过滤宣称成访问隔离。

固定 Hermes 管理的实际 Python 环境通过本机预检入口验证，已同步安装源，并在真实 MemoryManager 的虚构临时目录中核对与现有适配器兼容。现有 CLI 每次调用加载新脚本，无需重启应用或服务，也不运行 setup_profile.py / setup_jobs.py。
