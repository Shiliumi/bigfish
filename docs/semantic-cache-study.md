## 参考与取舍

[Qdrant 的模型迁移文档](https://qdrant.tech/documentation/tutorials-operations/embedding-model-migration/) 提醒：后台重编码读完文本以后，来源可能被并发更改，随后写回的向量就会对应旧文本。文档建议迁移期间暂停已有记录的修改和删除。大肥鱼要允许聊天中纠错，因此实验采用来源版本检查与返回前重读，而不要求用户暂停纠错。

[Chronicle 的固定版本源码](https://github.com/indigokarasu/chronicle-agent-context-and-memory/blob/92e4351a852117a11542210d06e8e5bfb61c3f1a/engine/vector_cache.py) 使用进程内向量副本减少重复读取，并检查底层表的变化。本实验沿用大肥鱼自己的来源版本与模型标识，先保存 float32 向量，验证落盘复用；没有引入其插件、复制实现或新建常驻 embedding 服务。[社区的过时记忆讨论](https://www.reddit.com/r/AI_Agents/comments/1wvvv5e/how_do_you_stop_your_agents_from_using_outdated/) 也提出了派生索引和原始来源应分开处理的问题；论坛经验只用于提出测试边界，不作为正确性证明。

## 缓存契约

`scripts/fish_semantic_cache.py` 只用 Python 标准库，自己不加载模型。调用方显式传入已打开的 Journal 与模型身份；只有实例化才创建缓存。正式适配器没有导入它，`install_memory.py` 也没有安装它。

- 原库 `episodes.sqlite3` 保持权威，缓存写到同一记忆目录的 `semantic-cache.sqlite3`；不允许缓存越出项目，或通过链接指向原库。来源读取使用新的只读连接，避免借用调用方未提交的修改或旧快照。
- 模型身份包括仓库、revision、权重和 tokenizer 校验值、维度、池化及查询指令配置，加上窗口与归一化流水线版本。缓存同时绑定来源路径和文件身份；不兼容模型、另一个项目或替换后的来源文件不接受原任务。
- 内存中的编码任务携带来源编号、revision、有效记法及内容指纹。更正过的经历只编码当前 summary，原始旧 excerpt 不再作为当前记法。窗口和别名保持与前次实验一致。
- SQLite 缓存只存标识、版本、指纹和归一化 float32 向量，不重复存原话。向量仍是私人派生数据，**不能称为匿名或不可反推**；缓存及其 sidecar 均受现有 Git 忽略规则保护。
- 写入前检查来源，缓存事务内再检查，提交后再读一次来源。完整窗口在一个缓存事务内替换；错误回滚。模型结果迟到、来源已更正或删除时拒绝写回。非有限值、零向量、维度或窗口数量不符时不替换有效缓存。
- 排名先过滤当前会话和调用方给的范围，只返回带版本的候选；`resolve` 在实际取文字前重新核验来源，返回当前记法和来源元数据。调用方不能把先前取出的候选当成永久有效文本。
- 健康缓存打开和查询不需要写事务，也不重复安排来源编码；损坏的 blob 跳过并移除，后续可重建。较新 schema 拒绝打开，不降级覆盖。

两个数据库之间没有跨库原子提交：来源仍可能在最后一次读取以后变化。返回前的核验约束的是那次读取所见版本，不保证交给模型后还能撤回已有上下文。遗忘与到期后，旧向量在**下一次缓存访问**才清理；这不是同步物理删除，也不清除原始 Hermes 会话、供应商记录或私有备份。把它接入应用前，需要明确处理删除链路、超时与退回词法检索。

## 真实模型复核

复用前次固定的中文 BGE ONNX 权重与独立 Python 3.12 环境。依赖与模型下载方法见 [原实验](semantic-memory-study.md)。本脚本不联网、下载模型或调用付费 API。

```bash
python3 -m unittest discover -s scripts -p 'test_semantic_cache.py'
.setup/semantic-runtime/bin/python scripts/eval_semantic_cache.py --model-dir .setup/semantic-model --output .setup/semantic-cache-results.json
```

三份既有虚构数据合并到临时库：`memory_replay.json`、`semantic_transfer.json` 与 `lexical_precision.json`，共 56 条当前有效经历、61 个窗口、154 个查询。每条查询先重新编码做参考，再与重新打开的持久缓存比较。沿用先前固定的 0.55 相似度、0.06 前两名差距门槛，未重新挑选门槛。

| 本机一次运行 | 结果 |
| --- | --- |
| 前五名排序与重新编码一致 | 154/154 |
| 固定补充门槛的选择一致 | 154/154 |
| 最大分数差 | 约 9.52 × 10⁻⁸ |
| 重新打开后来源编码任务 | 0 |
| 健康查询的缓存逻辑写入 | 0 |
| 初次准备、编码、提交 61 个窗口 | 约 1,017 ms |
| 仅排名并重读来源取文，中位数 / P95 | 约 8.65 / 8.75 ms |
| 模型校验与加载 | 约 194 ms |
| 热进程单查询编码中位数 | 约 3.58 ms |
| checkpoint 后缓存 SQLite 主文件 | 278,528 字节 |
| 完整实验进程峰值内存 | 约 392.7 MiB |

查询本身仍需编码，缓存只省掉未变来源的重复编码。这里的局部耗时不包括正常应用启动、网络模型生成、整个聊天延迟或大库表现，单次测量也不是稳定性能保证。主库行在编码与查询前后逐项一致。

另用真实编码结果验证十三个生命周期断言：更正后拒绝迟到写入及先前候选、只重新编码变化的来源、只取当前更正记法、遗忘后拒绝迟到写入及旧候选、下次访问清理向量、到期边界不取文并清理、别名变更拒绝旧任务、过期来源不再编码，以及模拟不兼容模型身份后原工作者失效而新缓存仍可用。模型切换测试改变身份标识，编码器本身仍是同一个固定权重，不是两个真实模型的质量对比。

二十项无模型测试还覆盖缓存有另一个写事务时读取已提交数据、来源在缓存提交前后变化、来源文件替换、完整窗口事务回滚、损坏 blob、项目隔离、来源未提交修改、较新 schema 和原库链接保护。

本轮只验证**缓存保持检索行为以及来源约束**，不把一致性当成相关性提升。既有查询已经被开发者查看，也不是新的盲测。模型原来可能误取的查询仍可能误取；没有生成答案测试，更没有真实聊天成功率或 token 节省率。当前词法召回本来就不调用 embedding API，因此实验零 API 开销不等于正式账单已经降低。

后续已通过 [同库事务与持久触发器](semantic-cache-transactions.md) 让来源更正、遗忘和向量移除一起提交。可移植的可选运行时、超时降级，以及不同对象、否定关系与无关查询中的误联想仍待处理；达到接入条件后再进入聊天，不为缓存本身增加设置页面。
