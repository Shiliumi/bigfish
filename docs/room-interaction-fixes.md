小屋交互修复 · 2026-11-02

本轮修复雪景几乎不可见，以及按下人物时跳位、连点时反复切换动画的问题。应用原生壳仍为 1.15.0，本地界面已重新构建并载入。

**雪景**

旧代码把 PointsMaterial.size 设为 0.045，误把世界单位当成像素。正交相机下的粒子不会按透视距离放大，因此即使选择了雪，粒子也几乎不可见。该参数的像素单位及透视相机限制见 [Three.js PointsMaterial 文档](https://threejs.org/docs/pages/PointsMaterial.html)。

修正为 3.6 像素的柔边雪花，保留窗口深度遮挡；雪天天空改为阴天色调。独立的粒子初始位置、速度与横向摆动避免形成原先整齐的斜线。粒子数仍为 72，不新增模型调用。

**人物点击**

全局 `button:active:not(:disabled)` 的 transform 覆盖了人物用于定位的 translate，造成按下时跳位。人物的三维投影定位现在放在外层锚点，点击按钮有固定的媒体画幅，按压不改变 transform。视频加载、静态海报、招呼气泡和动作切换都不会改变锚点尺寸。

连续点击不再切换 greeting 开关；已经在打招呼时保持当前动作，按片长结束后再回到实际活动状态。图形上下文丢失期间保留锚点，只暂时隐藏它，避免恢复后人物丢失定位引用。

**验证**

- 生产构建通过，73 项 Node 检查通过；本轮仅修改界面，没有重装记忆适配器或变更用户档案。
- 实际 macOS WKWebView 已检查修正后的雪花与人物招呼。
- 使用与产品相同的组件和全局 CSS，在独立虚构状态页面检查了普通视口与 520×420 视口。1 秒及 900 毫秒按压时，按下、按住、松开的人物边界一致；按钮 computed transform 均为 none。
- 连续点击后视频保持招呼来源，没有在 greeting 与 idle 之间来回切换；最小视口页面可滚动且没有横向溢出。
- 隔离页面的模拟隐藏与恢复正常；强制 WebGL 上下文丢失时显示恢复提示并保留锚点，恢复后锚点位置和视频正常。重复切换晴、雨、雪未触发图形恢复错误。
- 粒子位置检查覆盖一日时长内的不同采样时间，确认落点始终位于窗口内。这不等于完成一日运行或性能测试。

隔离页面只使用虚构活动状态，不读取真实聊天、记忆或模型配置。可复查以下交互，不把静态源码断言当作浏览器行为验证：
