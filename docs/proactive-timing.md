# 主动消息的打扰时机

应用 1.14.3 将已有的打扰判断接到投递、桌宠气泡和系统通知。没有增加控制项、任务或模型调用，界面布局保持原样。

此前只看最近交互时间，长回复超过冷却时间后仍可能投递；桌宠只在入队时验证消息年龄，等待后的旧消息仍可能弹出；系统通知允许一天内未读消息补弹，也没有统一看当前活跃状态。

现在主聊天仍在生成时继续等待，完成或最后一个活跃连接结束后重新计算默认 10 分钟的安静间隔。多窗口仍有活跃观看者时不会误清 busy。原生窗口按键、点击和桌宠交互会即时影响本机打扰门控；向服务端的 presence 请求保持节流，不记录按键内容，也不监控其他应用。

自动弹出只接受投递后 15 分钟内、尚未读、尚未提醒、未过自身有效期且兴趣仍有效的来信。桌宠真正出队时再检查一次；读过、已提醒或撤回兴趣的排队内容会移除。原消息保留在来信里，15 分钟是弹出窗口，不是删除期限。早晚问候仍受自身短窗口约束。桌宠可见时优先用气泡，隐藏时才走系统通知，避免两个自动表面重复提醒。用户主动选择的气泡预览保留。

原生端只信任最近 10 秒的可打扰快照；状态缺失、过期或不可确认时等待。现有夜间、每日上限、消息间隔和暂停设置继续生效。来信入口和未读数仍可供用户主动查看。

## 依据和验证

设计参考 [Proactive Service Agents 的论文摘要](https://arxiv.org/abs/2609.03727) 对时机、保持安静、打扰成本和用户负担的讨论，仅作设计参考，没有复现其评测。

67 项 Node 检查通过，包含长回复超过冷却时间仍等待、结束后重算冷却、跨窗口 busy 生命周期、旧消息与已读/已提醒消息保留但不弹出、兴趣选择及 API 字段约束。Swift 的门控和队列使用假时钟验证等待、过期、失效快照和撤销；现有桌宠行为与探头检查通过。TypeScript/Vite 构建、原生编译和安装成功，实际界面恢复既有聊天且在线。没有注入真实测试来信或发送付费聊天请求。

这些是本机轮询与时间戳判断，不能保证任意时序下绝无抢跑；两个自动提醒表面的切换也不是跨进程原子事务。服务端的最近活动时间仍在内存里，服务重启会重置，原生本地活动门控提供额外约束。它不判断用户在其他应用里是否忙碌，也没有引入全局输入监听。

已有安装先在应用空闲且没有草稿时退出，构建前端、重启本项目内部服务、执行 `python3 scripts/build_app.py` 后再打开应用。不需重设人设、模型或任务。升级保留私人备份，应用备份用 `.app-backup` 后缀，避免系统当作第二份可启动应用。
