# 冲浪中断与本地收尾恢复

2026-10-29，后台预算适配器 1.0.1 补齐冲浪出发记录与真实执行状态之间的联系。应用仍为 1.14.2，记忆适配器仍为 1.6.1，没有新面板、工具、定时任务或付费模型调用。

## 查阅与实际问题

[社区关于重复检索的讨论](https://www.reddit.com/r/LLMDevs/comments/1xc3c63/how_do_you_stop_your_agent_paying_twice_for/) 提到复用、时效与调用记录；帖内节省比例是个人经验，不作为本项目指标。本机已有无事不唤醒的预检和逐请求账本，本轮没有再建另一套调度或缓存。检查时发现三条出发记录长期为 started，而对应定时执行已经结束，没有收尾回执。

固定 Hermes 的 [执行审计实现](https://github.com/NousResearch/hermes-agent/blob/bf0203a794a07aac3ff764972ab9087baa4e4f4e/cron/executions.py) 将 completed / failed / unknown 作为终态，unknown 需要上游核对执行归属；[执行身份实现](https://github.com/NousResearch/hermes-agent/blob/bf0203a794a07aac3ff764972ab9087baa4e4f4e/cron/execution_identity.py) 则用 ContextVar 绑定本轮身份，并排除委派子代理。项目只读这些来源，不修改上游代码、审计状态或进程，也不因“过去很久”就断言任务结束。

## 两条恢复路径

已有 prepared 收尾回执，说明完整候选之前已通过验证，只是多文件提交没有全部完成。出发预检在本机先用原计划恢复，沿用现有文件前像、来源、人设与锁检查；恢复成功后回执转为 committed。重跑不会重复生成观察、问题或来信。外部文件已经改变时停止覆盖；prepared 仍未处理时，手动 begin 也不开始新出发。

没有回执时，程序只能核对状态，不能补写报告或猜测读到了什么：

- 预算中间件从 Hermes 的可信当前执行身份取得 job_id 和 execution_id，按实际 session_id 的 SHA-256 保存两个编号。文件不含明文会话编号、提示、网页、密钥或模型输出，位于已忽略的 `data/curiosity/owners/`。
- `begin` 仅在真实 cron 环境中，以当前会话找到对应编号，再只读本项目的 jobs.json 和 executions.db，确认恰为仍运行的 fish-surf。缺失身份、其他任务、歧义或读取失败时保留未绑定状态，不从“有一个任务在跑”推测归属。
- 后续预检只对已绑定出发检查终态及完整时间范围。明确执行结束且没有回执，才改为 interrupted，outcome 留空。正在运行的记录即使很旧也不动；未知归属、其他项目或未来结束时间也不动。
- interrupted 不等于完成、无聊或访问受阻，不改变兴趣、阅读证据、人格倾向，不制造来信。仍计入当天出发次数，不退还已花 token 或自动重开一轮。预算及主聊天规则不变。

整理只读本项目最多最近 1,000 条该任务的审计；审计被清理、身份文件缺失或运行环境不提供身份时，会保留 unresolved，需要维护者核对，不声称所有中断都能自动识别。身份元数据目前按会话保留，未增加自动清理任务。预检处于暂停或租约保护期间仍沿用原来的跳过规则。

## 维护与验证

```bash
python3 scripts/install_budget.py
python3 scripts/surf_complete.py --recover
python3 scripts/curiosity.py reconcile
python3 -m unittest discover -s scripts -p 'test_*.py'
```

更新预算适配器后，空闲时重载后台插件及内部接口；无需重建应用、改人设或重建 cron。`reconcile` 只修改已绑定且证据充分的出发状态，不恢复事务；应先执行 `--recover`。正常后台预检会自动按这个顺序执行，无需模型调用这些维护命令。

历史出发没有新版绑定，默认保持原样。维护者备份并核对实际执行后，可明确运行 `curiosity.py reconcile --legacy`：只接受唯一的终态时间窗、无活动执行和无收尾回执。这个关联弱于预先绑定的身份，单独标记为 legacy_time_window，不自动套用到历史记录。本机此次明确核对并修复了三条，原有完成记录和兴趣问题保留；没有借此生成发现。

252 项 Python 检查通过。新增检查覆盖身份与会话隔离、正在运行但很旧的执行、三种终态、其他任务、歧义与未来时间、手动历史修复、prepared 的幂等恢复、外部编辑冲突、引用源越界，以及预检不在 dry-run 中改写出发状态。这里的 dry-run 仍沿用已有账本检查，不承诺整个进程完全不写文件。

还用已安装预算适配器、固定 Hermes 的实际 cron 身份与终端环境桥，在临时虚构目录中验证身份能传到工具进程并正确绑定、再核对终态；没有调用模型供应商。自然触发的下一次本机定时执行也产生了可与审计匹配的身份元数据，没有人为发起额外冲浪。部署前在线备份并核对已有记忆、预算流水、额度、私人设定和三个任务定义保持不变。

本轮减少的是已验证事务恢复时对模型补写和重复操作的依赖，并修正状态真实性。没有测得日常 token 节省率，没有据此调整缓存计价、后台总 token 限额或宣称冲浪质量提升。
